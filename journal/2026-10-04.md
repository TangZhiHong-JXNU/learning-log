## 二、今天真正学到的是两个套路

### 套路 1：flag + break = "默认 + 证伪"

判断素数的关键不是算法，是思维：

- "**是**素数"要用 2…n−1 全部试完才能下结论 → 很难证
- "**不是**素数"只要找到一个因子 → 一个反例就够

所以写成：先假设是素数（`isPrime = 1`）→ 专门找反例 → 找到就推翻（`isPrime = 0`）+ 收工（`break`）。

这就是"无罪推定"：先假定无罪，由检方举证；举不出证据就是无罪。

（`isPrime` 是 **flag 变量**，跟整数反转里的 `sign` 是同一类东西——只管一个状态的小变量。）

### 套路 2：一件事一个变量

这条今天出现了**三次**，才意识到它是条通用原则：

| 场景 | 被塞进同一个变量的两件事 |
|---|---|
| 整数反转 | 符号 vs 数值（→ 拆出 `sign`） |
| 阶乘 | 输入的 `n` vs 计数的 `i`（→ 拆出 `i`） |
| 100 以内素数 | 循环控制 vs 判定结论（→ 拆出 `isPrime`） |

**一个变量只担一件事。** 想让它兼职的时候，先问自己：改一处会不会牵连另一处？

## 三、今天的坑（全都实测过）

1. **把"除不尽"当成结论** —— 方向反了。除不尽只是"没找到证据"，不构成任何结论。
   只有 2…n−1 全试完、一个因子都没找到，才能说它是素数。
2. **以为 break 导致进不去 else if** —— 错。它俩是**同一个原因（`if` 成立）的两个果**，不是因果。
   `if` 一成立，后面的分支**连条件都不评估**（实测：条件是恒真函数，被调用 **0** 次）。
3. **`isPrime` 忘了每轮重置** —— 输出只剩 `2 3`（25 个变 2 个）。程序不报错，答案悄悄错。
   判据：**这一轮要不要用到上一轮的值？**
   要 → 累积型（`sum` / `result` / `cnt`），不清；
   不要 → 独立型（`isPrime` / `sign`），每轮清干净。
4. **内层计数器也叫 `n`** —— 死循环。外层 `n++` 刚加到 3，又被内层重置回 2。
   铁律：**内外两层各用各的变量名，绝不共用。**
5. **条件写成 `cnt <= 50`** —— 多打印一个（51 个）。计数器从 0 起、+1，条件就写 `< 目标`。
6. **想用浮点数判素数** —— 能跑，但忘写 `(double)` 就崩（整数除法先发生）。
   而且浮点相等本来就不可靠（实测 `0.1 + 0.2 == 0.3` 结果是 0）。
   **能用整数干的事，别请浮点数出场。**

## 四、"位置决定频率"（今天最有用的一句话）

同一个语句，写在不同位置，执行次数完全不同：

| 写法 | 位置 | 执行次数 |
|---|---|---|
| `int isPrime;`（定义） | `main` 开头 | 整个程序 **1 次** |
| `isPrime = 1;`（重置） | 外层循环体**里面** | **每轮 1 次** |

变量不是每轮出生一次，**是一次出生、反复改值**，寿命 = 它所在的那对 `{ }`。
所以上一轮被写成 0 的 `isPrime`，会带着 0 进入下一轮 —— **C 不会替你归零。**

（顺带认了两个新词：`int i;` / `int isPrime = 1;` 直接写在循环体里 → 每轮**新建**变量，
就不用再手写重置。这是同一件事的另一种写法。）

## 五、顺便搞清的几件事

- **`if / else if / else` 是从上往下扫，撞到第一个成立的，做完就走**，
  后面的分支连条件都不评估（"没评估"跟"评估后不满足"是两回事）。
- **`break` 只管循环，不管 `if`**：写在哪个循环里，就跳出那一层，外层不受影响。
- **`else` 不是 `if` 的标配**，只在"另一种情况也有话说"时才写；
  没话说（外层）或已在别处处理（靠初值），写了就是噪音。
- **`for` 不是新语法**：只是把 `while` 散在三处的零件（初始化 / 条件 / 步进）收进了头部一行。
