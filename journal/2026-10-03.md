## 一、转 PDF 踩的 7 个坑

### 1. 在「预览界面」里改文档 → Ctrl+A / Ctrl+S 全部失灵
现象：标题变成蓝色居中，`---` 被画成一条横线。
真相：那是**只读的渲染视图**，不是编辑器。
**规则：预览 = 只能看，不能改。** 要改就回 VS Code 的编辑区。

> 我连续两次遇到"按键没反应"，其实是同一个原因。

### 2. 打开的是 `.md` 而不是 `.txt` → `#` 和 `---` 会被打进 PDF
markdown 里的 `#` 是排版指令，Word / WPS 不认，会原样印出来。
**规则：交作业用纯文本版 `.txt`，`.md` 只是写作用的草稿。**

### 3. Ctrl+A 全选没反应
两种可能：焦点不在正文 / 当前是只读视图。
**兜底操作**：先在正文里点一下鼠标，再按 `Ctrl+A`；
还不行就走菜单：**开始 → 编辑 → 选择 → 全选**，或者干脆用鼠标拖。

### 4. 不知道怎么居中
**`Ctrl+E`** 就是居中。
配套：Ctrl+L 左对齐 / Ctrl+R 右对齐 / **Ctrl+J 是两端对齐**（容易按错，按下去字会被拉开）。

### 5. 找不到导出按钮
WPS 里三条路都能出 PDF：
- **文件 → 输出为 PDF**
- `Ctrl+P` → 打印机选 **「导出为 WPS PDF」**
- `F12` 另存为 → 保存类型选 **PDF 文件 (\*.pdf)**

### 6. 导出后在桌面找不到文件
**WPS 默认把 PDF 存到它的云盘**，不是桌面：
```
C:\Users\34008\WPS Cloud\WPSDrive\1316010268\WPS云盘\
```
**规则：导出前先看清保存位置。** 实在找不到就在资源管理器里搜文件名。

### 7. 导出时文档里还留着选区
如果导出前文字还是蓝底高亮（处于选中状态），WPS 可能只导出那一部分。
**规则：导出前在正文里点一下，取消选区。**

## 二、发邮箱踩的 5 个坑

### 1. 附件没传完就点发送
上传要时间。**等附件列表里显示文件名和大小**（比如 138 KB）再点发送，
否则老师收到的是空附件。

### 2. 文件名写错
老师要求的是 **`唐志鸿+学号`**，有两个地方容易错：
- 漏掉中间那个 **`+`**（`Shift` + 等号键）
- **学号打错** —— 学号错一位，老师归档时直接对不上人

### 3. 以为"删除"能撤回
QQ 邮箱的删除**只删自己邮箱里的记录，老师的收件箱那封还在**。
而"撤回"功能**只对发往 QQ / Foxmail 邮箱的信有效**，发到 aliyun.com 撤不回来。

### 4. 发错之后的正确补救
**补发一封正确的，正文里说明一句**：
> 老师您好，刚才那封有误，请以本封为准，给您添麻烦了。

老师不会因为收到两封扣分，**装作不知道才会**。

### 5. 发件人显示的是网名
QQ 邮箱默认用 QQ 昵称发送。
**设置 → 账户 → 发件人昵称 → 改成真名**，改一次永久生效。

# 五、晚上：C 语言 4.1.x 循环（我口述，整理版）

## 5.1 while 和 do-while 的区别

| | while | do-while |
|---|---|---|
| 顺序 | **先看条件，成立才做** | **先做一次，再问要不要继续** |
| 最少执行 | **0 次**（条件一上来就假） | **1 次**（无条件先做） |
| 什么时候用 | 次数不定，可能一次都不用做 | 至少要干一次的场合 |

数位数那道题就是活例子：`while (x > 0)` 输入 0 → 一次不进 → 输出 0 位（错）。
三种补救都对：① 循环外先手动做一次 ② 换成 do-while ③ `int n = 1` 配 `while (x >= 10)`。

## 5.2 学会用极端值验证（这条是我自己总结的，很重要）

> **程序写完，先喂它几个"极端数据"：0、1、最小的、最大的。**

正常数据全对、一到边界就露馅的 bug 叫**边界 bug**。
PAT 判题一定会拿边界数据测，"样例过了、提交 0 分"八成死在这。

## 5.3 rand() 生成随机数

```c
#include <stdlib.h>      /* rand / srand 住这儿 */
#include <time.h>        /* time 住这儿 */

srand(time(0));          /* 播种子：不写的话每次开程序都是同一个数 */
int number = rand() % 100 + 1;    /* 把 0~32767 压到 1~100 */
```

**srand 保证的是"不同时刻不一样"，不是"同一时刻能变出不同的数"。**
实测一秒内连点三次运行，吐的是同一个数——因为 `time(0)` 精确到秒。

## 5.4 先画流程图再写代码

复杂逻辑先在纸上画清楚"从哪进、从哪出、什么时候停"，再动手敲。
画不出来的循环，写出来的代码一定是乱的。

## 5.5 scanf 和死循环（这条我原来的说法不准，已修正）

❌ 我原来的说法：**"scanf 一定要在循环里，不然死循环"**
✅ 正确的说法：**让循环条件走向假的那个动作，必须在循环体内。**

scanf 只是"给变量重新赋值"的手段之一，`x /= 10`、`n++` 也一样能干这事。
四个场景实测：

| # | scanf 在哪 | 循环体里有没有人改条件变量 | 结果 |
|---|---|---|---|
| ① | 外 | 没人改 | ❌ 死 |
| ② | 外 | 有（`x /= 10`） | ✅ **正常结束** |
| ③ | 里 | 改了，但条件看的不是它 | ❌ 照样死 |
| ④ | 里 | 想改，但**没读进去** | ❌ 照样死 |

**分开记两句：**
- **只读一次的数据 → scanf 放循环外**（比如先读一个 n，再 for 跑 n 次，PAT 常见格式）
- **每轮都要重新读的 → 放循环内**（猜数游戏就是）

**④ 最阴**：`scanf("%d", &a)` 遇到字母读不进去，**也不把字母拿走**，
它就赖在缓冲区里，下一轮还是撞上它 → 永远循环。
> scanf 有返回值 = **成功读入的变量个数**。
> `while (scanf("%d", &a) == 1)` —— 读到 EOF 或非法输入自动停，这是 PAT 多组数据题的标准骨架。

## 5.6 用 % 和 / 拆数字

```c
x % 10      /* 取个位数 */
x / 10      /* 去掉个位数 */
x % 100     /* 取最后两位，结果一定 < 100（0~99） */
x / 100     /* 去掉最后两位 */
```

正负数的边界：C 里**余数的正负跟着被除数走**，`-150 % 100` 得 **-50**，不是 50。

## 5.7 switch-case：case 是"上车点"，break 才下车

我自己的比喻（挺好的，保留）：**case 像公交站，匹配上了就上车；
车会一直往前开，只有遇到 break 才停。**

所以漏写 break 会"**落空**"——从 case 7 一直执行到 case 6、case 5……值被反复覆盖。
（故意利用这个特性可以让多个 case 共用一段代码。）

## 5.8 级联 if-else

多选一时用 `if → else if → else if → else`，**自上而下，命中一个就停**，不会乱。
最后的 `else` 是"剩下的全部"，所以不用再写条件。

## 5.9 printf：写在里面，运行的时候就能看见

```c
printf("in loop: x=%d n=%d\n", x, n);
```

插在关键位置，等于**在程序里装摄像头**，能亲眼看见变量一轮轮怎么变。
这是最朴素的 **debug**（de + bug = 捉虫）手段。

⚠️ **交 PAT 前必须删掉这些调试 printf**——PAT 逐字符比对输出，
多一个字就是"格式错误"，答案对了也 0 分。

## 5.10 初值兜底 + if 修正（"打擂台"）

比较 A B C 大小时，不用写一堆 else：

```c
int max = a;              /* a 先站上擂台 */
if (b > max) max = b;     /* b 挑战 */
if (c > max) max = c;     /* c 挑战 */
```

这就是翁恺 3.2.4 讲的**打擂台**。核心思想：

> **初值负责"大多数"，if 只管"例外"。**

好处有两个：分支更少，而且**变量从出生起就有值**，不怕"未初始化"这个坑。
同样的套路还有数位数里的 `int n = 1;`（任何数至少一位）。

**边界**：只有当"剩余情况答案一致"时才能这么写。
分段函数那种三个答案互不相同的，老实写 else if。

## 六、今天口述里的 4 处术语正名

| 我原来怎么说的 | 正确的说法 |
|---|---|
| do-while 是"**先进行编译**，再进入循环" | 是**先执行一次循环体**，再判断。编译（compile）是把代码翻译成 exe 的过程，跟循环先后**完全无关** |
| printf 是"在**编译的时候**输出" | 是**运行的时候**输出。编译时屏幕上什么都不会有 |
| "scanf 一定要在循环里" | 见 5.5——本质是"**条件变量必须在循环体内被重新赋值**" |
| "取余可以得到它的个位数…" | 收紧成两句：**`x % 10` 取个位，`x / 10` 去个位** |
