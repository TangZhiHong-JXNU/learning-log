## 零、先把题目读成一句话

> 给一个不超过 6 的正整数 A，把 **A、A+1、A+2、A+3** 这四个数字**各用一次**，拼成三位数，全打出来。  
> 从小到大，每行 6 个，行末不留多余空格。

A=2 时，四个数字就是 `2 3 4 5`。

**这道题只有这一句是新的，其余全是你会的东西。**

## 一、你"没思路"是正常的，原因很具体

前五周你写的所有循环题，都是**单层循环** ——  
数位数、逆序、判素数、求最大公约数，一次只需要盯住一件事。

这题不一样：你要同时决定**百位是谁、十位是谁、个位是谁**，三件事互相独立。  
**一个循环只能管一件事，所以它需要三层。**

> 不是这题难，是你第一次遇到「一层管不过来」的题。跨过这道坎，后面的九九乘法表、  
> 二维数组遍历全都是同一个模式。

## 二、第一步：把"三位数"拆成三个格子

|      | 百位      | 十位      | 个位      |
| ---- | ------- | ------- | ------- |
| 能放什么 | 2 3 4 5 | 2 3 4 5 | 2 3 4 5 |
| 怎么数  | 4 种     | 4 种     | 4 种     |

每个位置都**独立**从 4 个数里挑 → `4 × 4 × 4 = 64` 种摆法。  
再筛掉「有两位相同」的 → `4 × 3 × 2 = 24` 个。

**看出什么了吗：24 = 4 行 × 6 个。**

题目那句「每行 6 个」不是随便定的 —— **每行 6 个，正好就是「百位固定时」的全部结果**。  
本机实测（A=2）：

```
[百位 2] 234 235 243 245 253 254   <- 本行 6 个
[百位 3] 324 325 342 345 352 354   <- 本行 6 个
[百位 4] 423 425 432 435 452 453   <- 本行 6 个
[百位 5] 523 524 532 534 542 543   <- 本行 6 个
合法总数 = 24
```

**这一条就是"没思路"到"有思路"的转折点**：换行不是随便数到 6 就换，  
而是**百位换了才换行**。

## 三、第二步：「从小到大」不用你写排序

这是本题最爽的一点 —— 排序是**白送的**，来自循环的嵌套顺序。

本机实测两种嵌套顺序（同一个 `if` 判断，只换里外）：

**外层管百位** → 输出有序：

```
234 235 243 245 253 254 324 325 ... 523 524 532 534 542 543
```

**外层管个位** → 输出乱掉：

```
432 532 342 542 352 452 423 523 243 543 253 453 324 524 234 534 ...
```

**为什么**：内层跑得最快、外层最慢。所以**谁当外层，输出就按谁的顺序排**。  
想从小到大（百位优先比），就得让**百位当最外层**。

> 你 4.3.3 学的三层循环（九九乘法表那类）就是这个结构，只是那次没人在意顺序。

## 八、最后一处暗门：十位换轮时，个位从哪儿开始？

这是自己盯输出更容易看错的一点。**十位从 2 变成 3 时，个位不是从 6 接着数，而是回到 A。**

原因藏在内层 `for` 的**第一个分号之前**：

```c
for (k = A; k <= A + 3; k++)
     ^^^^^   ← 这句不是"只执行一次"，每进一轮 j 都要重跑一遍
```

**一个 `for` 的三段各跑多少次**：

| 位置 | 名字 | 跑几次 |
| --- | --- | --- |
| `k = A`（第一个分号前） | 初值 | **每轮 j 一次** |
| `k <= A+3`（分号之间） | 条件 | 每轮 j **5 次**（多一次判断失败） |
| `k++`（第二个分号后） | 步进 | **每个 k 一次** |

本机实测（A=2，百位固定 2，故意先把 k 塞成哨兵值 99）：

```
[十位 j=2 这一轮开始] 此刻 k 的残留值是 99
      试 k=2  试 k=3  试 k=4  试 k=5
[十位 j=2 这一轮结束] k 停在 6          ← 加到 6 才发现超界

[十位 j=3 这一轮开始] 此刻 k 的残留值是 6   ← 上一轮留下的
      试 k=2  试 k=3  试 k=4  试 k=5    ← 6 被 k = A 覆盖掉了
[十位 j=3 这一轮结束] k 停在 6
```

**反证**（把 `k = A` 删掉，写成 `for (; k <= A+3; k++)`，先把 k 预置成 2）：

```
j=2  试 2 3 4 5  → k 停在 6
j=3  空          ← 6 > 5，一次都进不去
j=4  空
j=5  空
```

→ **没有那句 `k = A`，只有第一轮能跑。** 十位 2、3、4、5 各自完整走一遍个位，全靠它。

顺带两个你会问的：
- **为什么退出时是 6 不是 5 ？** 因为 k=5 跑完还要 `k++` 变 6，再拿 6 比一次条件，失败才退出。
- **它是"赋值"不是"再定义"** —— `for (k = A; ...)` 和 `for (int k = A; ...)`（C99/C11 里在括号内定义）行为一样，
  都是每轮重新开始；区别只在后者的 k 出了循环就没了。

## 十一、换行符加在哪？（2026-10-06 追问）

> 你的原话：「两个都要加，还是只用一个 printf 里面加？」

**都不是。换行符不该加在打印数字的那条 printf 里 —— 要另起一条。**

### 为什么：换行属于「行」，不属于「数字」

一条 printf 只负责一件事。打印数字这条的职责是"把这一个数写出去"，
一行有 6 个数，**行**这个概念比**数字**大一级。让它管换行，等于让"打数字"去管"分段落"。

### 位置：百位层循环体的末尾

```c
for (i = a; i <= a + 3; i++) {          /* 百位层 */
    for (j = ...) {                     /* 十位层 */
        for (k = ...) {                 /* 个位层 */
            if (i!=j && j!=k && i!=k) {
                printf("%d%d%d ", i, j, k);   /* 只打数字，不带 \n */
            }
        }
    }
    printf("\n");                       /* ★ 十位层整轮跑完，才换行 */
}
```

**为什么是百位层**：题目按百位分组（见 §三），**百位换人 = 换一行**。
所以要等十位层那一整轮（含个位层全部）跑完，才轮到换行。

### 实测：只换位置，输出天差地别（输入 A = 2）

| 写哪儿 | 代码 | 实测输出 |
|---|---|---|
| 写在格式串里 | `printf("%d%d%d\n", i, j, k);` | **24 行，每行 1 个** |
| 另起一条放百位层末尾 | `printf("\n");` | **4 行，每行 6 个** ✓ |

### ⚠️ 但换行一放对，立刻撞上第二个坑：行末空格

4 行那版的实测输出（`cat -A` 放大，`$` 是行尾）：

```
234 235 243 245 253 254 $      ← 254 后面那个空格多出来的
324 325 342 345 352 354 $
423 425 432 435 452 453 $
523 524 532 534 542 543 $
```

因为 `printf("%d%d%d ", ...)` 的**每个**数后面都带了空格，包括每行最后一个。

**这就是你 5.3.2 踩过的那个坑，第三次出现：「最后一个是特殊的」。**

### 思路（代码你自己写）

要让"每行最后一个数不带空格"，就得让打空格这个动作**知道自己是行末**。
两个常见方向，选一个：

1. **计数器法**：数通过了几个数，每 6 个一组 —— 是组内最后一个就不打空格、改打换行。
2. **调换顺序**：不在数字**后面**打空格，改成在数字**前面**打（每行第 1 个不打）——
   这样行末天然干净。判断"是不是第 1 个"同样要靠计数器。

> 注意：一行固定 6 个不是巧合 —— 百位定了以后，十位 3 种 × 个位 2 种 = 6，
> 所以 A = 2~6 都是每行 6 个。用计数器是安全的。

#### ② 数字之间没有分隔空格（只差这一点不 PTA）

| 写在哪 | 输出 | 判定 |
|---|---|---|

| `"%d%d%d"`（你现在的） | `234235243245253254` | 粘成一坨 ✗ |
| **空格打在数字前面、跳过每行第一个** | `234 235 ... 253 254` | ✓ |

**为什么"打前面、跳过第一个"能解决**：空格的作用是"分隔两个数"。
一行有 6 个数，需要 **5 个空格**，而空格总归长在"某一个数"的旁边 ——
- 打在后面 → 长在第 6 个数后面 → **跑到行末去了** ✗
- 打在前面 → 长在第 2~6 个数前面 → **正好 5 个，行末天然干净** ✓

**解法 A —— `first` 标志（空格打在前）**

```c
for (i = a; i <= a + 3; i++) {
    int first = 1;                    /* 本行还没打过数字 */
    for (j = ...) {
        for (k = ...) {
            if (i!=j && j!=k && i!=k) {
                if (first == 0) printf(" ");   /* 不是第一个，才先补空格 */
                printf("%d", i*100 + j*10 + k);
                first = 0;                     /* 打完就不是第一个了 */
            }
        }
    }
    printf("\n");
}
```

**解法 B —— 计数器（空格打在前）**

```c
for (i = a; i <= a + 3; i++) {
    int n = 0;                        /* 本行已打几个 */
    for (j = ...) {
        for (k = ...) {
            if (i!=j && j!=k && i!=k) {
                n++;
                if (n > 1) printf(" ");
                printf("%d", i*100 + j*10 + k);
            }
        }

    printf("\n");
}
```

```
423 425 432 435 452 453
```

（跟你 16:52 弄明白的"内层计数器每轮要重置"是同一件事，这次用"就地声明"白拿重置。）

## 十五、`first` 到底在干什么（2026-10-06 18:25 追问）

### 一句话：它不是计数器，是**状态标记**

`first` 记的不是"已经打了几个"，而是一个**是否**：

> **"本行的第一个数，出现了没有？"**

- 旗子立着（`first == 1`）→ 本行还一个数都没有
- 旗子倒下（`first == 0`）→ 本行已经打过至少一个了

所以它叫 `first`（是不是第一个）而不是 `count`（第几个）。

### 三个动作点，缺一不可

```c
for (i = a; i <= a + 3; i++) {
    int first = 1;                        /* ① 出生 */
    ...
                if (i != j && j != k && i != k) {
                    if (first == 0) printf(" ");   /* ② 读 */
                    printf("%d", i * 100 + j * 10 + k);
                    first = 0;                          /* ③ 翻 */
                }
    ...
    printf("\n");
}
```

| # | 代码 | 作用 | 少写会怎样 |
|---|---|---|---|
| ① | `int first = 1;` | 每进一轮百位层，旗子立起来 | 变量不存在 → 编译不过 |
| ② | `if (first == 0) printf(" ");` | 旗子倒了才补空格 | 空格没条件了 → 行末又长一个 |
| ③ | `first = 0;` | 打完第一个立刻翻倒 | **一个空格都不打**（旗子永远立着） |

### 本机实测：一行之内 `first` 的真实取值

（百位 = 2 那一轮，在 `if` 里打印 `first` 的原值）

```
[百位层第 2 轮进场] first 被重新出生 = 1
    通过 234  | 检查时 first=1  ->  不打（本行第一个）
    通过 235  | 检查时 first=0  ->  打一个空格
    通过 243  | 检查时 first=0  ->  打一个空格
    通过 245  | 检查时 first=0  ->  打一个空格
    通过 253  | 检查时 first=0  ->  打一个空格
    通过 254  | 检查时 first=0  ->  打一个空格
[本轮结束] first 现在 = 0，下轮会被重新出生

[百位层第 3 轮进场] first 被重新出生 = 1      ← 又变回 1 了
    ...
```

**只有第 1 个数看到 `first == 1`，剩下 5 个都看到 0。** 正好 5 个空格，行末不长东西。

### 为什么必须声明在**百位层里面**

这是 16:52 那条"内层计数器每轮要重置"的**第三次出现**，但这次反过来用了：

| 声明位置 | 行为 |
|---|---|
| **百位层里面**（正确） | 每换一行重新出生为 1 → **自动重置** |
| 百位层外面 | 第一行结束留在 0，第二行接着用 0 → **行首多一个空格** |

实测（把 `int first = 1;` 挪到 `i` 循环外面，用 `cat -A` 放大）：

```
234 235 243 245 253 254
 324 325 342 345 352 354      ← 行首多一个空格（标红那个）
 423 425 432 435 452 453
 523 524 532 534 542 543
```

> 行末的空格和行首的空格是**同一类问题的两半**：都是"位置算错了"。
> 区别只在于一个在右边溢出，一个在左边溢出。

### 忘了 `first = 0;` 会怎样（实测）

```c
if (first == 0) printf(" ");
printf("%d", i * 100 + j * 10 + k);
/* 没有 first = 0; */
```

输出：

```
234235243245253254
324325342345352354
423425432435452453
523524532534542543
```

**这正是 17:36 那版的效果** —— 少了第 ③ 步，等于整个标志白设。

### 小结：一个通用套路

```
在每个"批"开始的地方，立一个标记（first = 1）
每碰上批里第一个东西，做完之后把标记翻倒（first = 0）
后面所有东西都靠这个标记判断"我是不是第一个"
```

这套"**行首标志**"以后还会反复用：打印逗号分隔的列表、输出 JSON 的数组、
拼 SQL 的 `WHERE` 条件……**凡是"第一个/最后一个特殊"的活儿都是它。**

## 十七、计数器该怎么用（2026-10-06 18:35 追问）

他问："计数器的话，在这里应该怎么用？" —— 六种写法全在本机跑过、diff 过。

### 六种写法实测对照（输入 2，基准 = `first` 版）

| 写法 | 判断空格的依据 | 换行放哪 | 实测 vs 基准 | 通用吗 |
| -- | ------ | ------ | -------- | ---- |
| V1 `first` | `first == 0` → 空格打**前** | 百位层末尾 | 基准 | ✓ 通用 |
| V2 计数 `n` | `n > 0` → 空格打**前** | 百位层末尾 | **逐字节一致** | ✓ 通用 |
| V3 计数 `n` | `n % 6 != 0` → 空格打**后** | 百位层末尾 | **逐字节一致** | ⚠ 依赖 6 |
| V4 计数 `n` | `n % 6 != 0` → 空格打**后** | `else printf("\n")` | **逐字节一致** | ⚠ 依赖 6 |
| V5 他那版 | 不判断，空格**全打后** | 百位层末尾 | 差 4 个空格 | ⚠ 通用但脏 |
| V6 反证 | `n % 5 != 0`（故意写错） | `else printf("\n")` | **全乱** | — |

**V2 和 V3 输出一模一样，但性质不同**：
V2 判断的是"**我是不是行首**"（`n > 0`），V3 判断的是"**我是不是第 6 个**"（`n % 6`）。
前者通用，后者把 `6` 写死了。

### 计数器管空格：两种写法

**写法甲（推荐，通用）—— 空格打在前面，用 `n > 0` 判断"本行开张了没有"**

```c
for (i = a; i <= a + 3; i++) {
    int n = 0;                                   /* 本行已打印几个 */
    for (j = ...) {
        for (k = ...) {
            if (i != j && j != k && i != k) {
                if (n > 0) printf(" ");          /* 本行已有内容，才补空格 */
                printf("%d", i * 100 + j * 10 + k);
                n++;
            }
        }
    }
    printf("\n");
}
```

**`n > 0` 和 `first == 0` 是同一件事的两种写法** —— 一个用数字记（几个），一个用旗子记（是/否）。
实测输出逐字节相同。

**写法乙 —— 空格打在后面，用 `n % 6` 判断"我是不是本行第 6 个"**

```c
                printf("%d", i * 100 + j * 10 + k);
                n++;
                if (n % 6 != 0) printf(" ");     /* 不是本行第 6 个，才补空格 */
```

### 计数器还能顺带管换行（V4）

```c
                printf("%d", i * 100 + j * 10 + k);
                n++;
                if (n % 6 != 0) printf(" ");
                else printf("\n");               /* 凑满 6 个就换行 */
/* 百位层末尾不用再写 printf("\n"); */
```

实测与基准**逐字节一致**。但这招更"脆" —— 见下面的反证。

```
                           543                    ← 连换行符都没有
```

行被劈成 5 个一组，而且**最后一行没有行尾换行** —— 因为 24 ÷ 5 除不尽，`n % 5 == 0` 永远等不到。

### ⭐⭐ 根子：两种判断的"信息可得性"完全不同

| 判断 | 什么时候能知道 | 代价 |
| -- | ------- | -- |
| "我是不是**第一个**？" | 数字**一到手**就知道（`n == 0`） | **当场可知** → 不用知道每行几个 → 通用 |
| "我是不是**最后一个**？" | 数字到手时**还不知道后面有没有** | 只能**提前把"每行 6 个"写死**在判断里 |

> **一句话**：判断"第一个"是**当场**的事，判断"最后一个"是**事后**的事。
> 所以 `first` / `n > 0` 天生通用；而 `n % 6` 必须依赖"每行恰好 6 个"这个前提。

（这题每行恒为 6 —— 百位定了以后，十位 3 种 × 个位 2 种 = 6 —— 前提成立，
所以 `n % 6` 能用。换成"每行 5 个"或"最后一行不满"的题，它就崩。）

### 三者优先级

1. **`first` 或 `n > 0`**（判断第一个）—— 通用、无前提，首选
2. **`n % 每行个数`**（判断最后一个）—— 只在"每行个数恒定"时可用，是个**隐藏假设**，要写注释
3. **不判断**（他那版）—— 最省事，代价是行末空格，靠判题忽略兜底
