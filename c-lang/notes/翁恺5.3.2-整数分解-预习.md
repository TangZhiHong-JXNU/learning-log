## 二、5.3.2 的逆序分解写法和 4.3.3 不一样，为什么？

**先说结论：不是因为 do-while「更简便」，而是因为两题的任务根本不同。**

### 4.3.3 的任务：把数整个逆过来，**合成一个新数**

```c
int n, rev = 0, digit;
scanf("%d", &n);

while (n != 0) {
    digit = n % 10;          /* 拆末位 */
    rev = rev * 10 + digit;  /* 拼到结果 */
    n = n / 10;              /* 砍末位 */
}
printf("%d\n", rev);
```

有 `rev`、有 `digit`，**要把每一位攒起来**。

### 5.3.2 的任务：**逐位打印**

```c
int n;
scanf("%d", &n);

do {
    printf("%d", n % 10);    /* 剥一位，直接打出去 */
    n /= 10;
} while (n > 0);
```

不需要 `rev`、不需要 `digit` —— **剥出来就扔，不攒**。

**代码变短，是因为任务变简单了（只要输出，不要组装），不是因为循环换了。**

### 那 do-while 在这里的真正作用是什么？

**它是被「输入 0」逼出来的。** 本机实测：

| 写法 | 输入 `1234` | 输入 `0` |
| --- | --- | --- |
| 4.3.3 版（`while` + 合成数） | `4321` ✓ | `0` ✓ |
| 5.3.2 版（`do-while` + 逐位打印） | `4 3 2 1` ✓ | `0` ✓ |
| 把 5.3.2 硬改成 `while` | `4 3 2 1` ✓ | **什么都不打印** ✗ |

原因：
- 4.3.3 那版 `n = 0` 时循环一次不进，`rev` 保持初值 `0`，**结果照样对** → 不需要 do-while
- 5.3.2 那版要「每一位都输出」，而 `0` 也是一位。`while` 一进门就问条件、条件假就整轮不做 → **0 这一位被漏掉**

> **`while` 先问再做，条件一假整轮都不做；`do-while` 先做一次再问 —— 所以它保证「至少执行一次」。**

顺带一个细节：4.3.3 的条件写 `n != 0`（能兼容负数），5.3.2 写 `x > 0`（只处理正数）。

## 三、一个自己想到的替代方案：「逆序一次，再逐位剥」

**思路**：老办法从**原数**剥出来是 5 4 3 2 1（逆序），那**先把数倒过来**再剥，剥出来不就正了吗？

**本机实测结论：对，但有个洞。**

| 输入 | 逆序一次 → 逐位剥 | 结果 |
| --- | --- | --- |
| `12345` | `12345` → `54321` → 剥 | `1 2 3 4 5` ✓ |
| `700` | `700` → `7` → 剥 | `7` ✗ 应为 `7 0 0` |
| `1200` | `1200` → `21` → 剥 | `1 2` ✗ 应为 `1 2 0 0` |

**死穴是末尾的零。** 根因：`700` 逆序成 `007`，而 `007` 作为一个**整数**就是 `7` —— **int 不存「前导零」**（4.3.3 那次「700 想变 007」的同一个坑）。

|  | 逆序法（自己想） | mask 法（视频用） |
| --- | --- | --- |
| 新增零件 | **零**，复用 `%10` `/10` | 多一个 `mask` 变量 |
| 末位不是 0 的数 | ✓ | ✓ |
| `700` / `1200` | ✗ 丢零 | ✓ |

**这条路在「字符串」里是成立的**（第 10 周）：`"700"` 逆序成 `"007"`，零一个都不丢。**暂时的手上没有能装住每一位的工具。**

另一个变体「把数字逆序两次」则完全无效 —— 逆两次等于恒等变换，白做（`12345 → 12345`，`700 → 7`）。

## 六、输出格式：末尾那个「凭空出现」的空格

题目要输出 `1 2 3 4 5` —— 数字之间要有空格。翁恺的写法是：

```c
int d = x / mask;
printf("%d", d);
if (mask > 9) {          /* ← 管的就是空格 */
    printf(" ");
}
x %= mask;
mask /= 10;
```

**它的作用不是「去掉空格」，而是「决定要不要打这个空格」。**

### 空格为什么会多出来

**n 个数字之间只需要 n−1 个分隔符**（5 个数字 → 4 个空格）。
但如果写成「每打一个数字就跟着打一个空格」`printf("%d ", d)`，
就会给出 **n 个** —— 多出来的那一个落在**末尾**。

```
无条件 printf("%d ")   ->   [1 2 3 4 5 ]    ← 末尾多一个空格
if (mask > 9) 才打     ->   [1 2 3 4 5]     ✓
```

（用 `|` 或 `[ ]` 把输出框起来，末尾空格就藏不住了 —— 终端上看不见它。）

### 凭什么认出「最后一位」：mask

`mask` 每轮末尾都 `/10`，序列是 `10000 → 1000 → 100 → 10 → 1`。
只有降到 `1` 的时候才是最后一位，所以 `mask > 9` 就是「这一轮后面还有位，需要空格」。

### 踩坑提示：别用 `x > 9` 判断

本机实测（输入 `100`）：

```
if (mask > 9)   ->   [1 0 0]    ✓
if (x > 9)      ->   [1 00]     ✗
```

原因：`x` 在循环里被 `x %= mask` 改掉了。`100` 到第二轮时 `x` 已经变成 `0`，
但后面还有位没输出 → 判断失灵。

**逐轮实况（本机实测，这是最硬的证据）：**

```
输入 12345（两种判据每轮答案都一样 → 看不出差别）
  x = 12345  mask = 10000   mask>9 ? 是   x>9 ? 是
  x = 2345   mask = 1000    mask>9 ? 是   x>9 ? 是
  x = 345    mask = 100     mask>9 ? 是   x>9 ? 是
  x = 45     mask = 10      mask>9 ? 是   x>9 ? 是
  x = 5      mask = 1       mask>9 ? 否   x>9 ? 否

输入 100（第 2 轮就分家了）
  x = 100    mask = 100     mask>9 ? 是   x>9 ? 是
  x = 0      mask = 10      mask>9 ? 是   x>9 ? 否    ← 这里分家
  x = 0      mask = 1       mask>9 ? 否   x>9 ? 否
```

**为什么分家**：`100` 后面两位是 `0`，被 `x %= mask` 切掉之后 `x` 直接变成 `0`（**int 不存前导零**），
可 `mask` 是按原数的位数算出来的，照常往下走。所以「还剩几位」只有 `mask` 说得准。

> `mask` 记的是**当前这一位的权重**（位置信息）；`x` 记的是**剩下的数值**（会被切碎）。
> 判断"还有没有下一位"要用位置信息。

> **这是通用问题，不只 C 有**：CSV 每行末尾多一个逗号、URL 拼参数多一个 `&`，
> 都是「分隔符比元素多了一个」。两种解法 —— 让**最后一个**特殊（后置判断，翁恺用的），
> 或者让**第一个**特殊（前置判断，一般要配一个 flag）。

## 七、校正版：这套程序是怎么一步步改出来的

> 全部数据来自本机实测（输出用 `[ ]` 框住，末尾空格才藏不住）。

### 阶段 1 · 逆序打印（能拆开，但空格多一个）

```c
do {
    printf("%d", x % 10);
    x /= 10;
} while (x > 0);
```

```
无条件 printf("%d ")   ->   [5 4 3 2 1 ]   ← 末尾多一个空格
if (x > 9) 才打空格    ->   [5 4 3 2 1]    ✓
```

⚠️ **校正①**：这个 `if (x > 9)` 写在**循环体里**。`while` 的条件自始至终是 `x > 0`，**没有动过**。
「改 while 条件」和「改循环体里的 if」是两件事，别记成一件事。

### 阶段 2 · 要正序 → 岔路分成两条

**不是同一条路继续改，是换思路另起一条。** 两条并列，只有一条走得通。

| | 岔路 A | 岔路 B |
| --- | --- | --- |
| 做法 | 先把数整个逆过来合成 `t`，再 `x = t` 逐位剥 | 用 `mask` 从高位往下切 |
| 新增零件 | **零**（复用 `%10` `/10`） | 多一个 `mask` |
| `700` | ✗ `7` | ✓ `7 0 0` |

岔路 A 实测：

```
输入 12345   [1 2 3 4 5]   ✓
输入 700     [7]           ✗ 应为 7 0 0
输入 1200    [1 2]         ✗ 应为 1 2 0 0
```

死穴是末位零：`700` 逆序成 `007`，而 `007` 作为整数就是 `7`。

⚠️ **校正②**：**两个 `t`，同名不同命。**

- 岔路 A 里的 `t` = 「**逆序后的新数**」，所以有 `x = t;` 把结果交回给 x
- 岔路 B 里的 `t` = 「**x 的副本**」，只为算 mask，原 x 一点也不动

复述时把这两处混成了一处，会导致复现代码时写错。

### 阶段 3 · mask 怎么算出来

| 算法 | `x=7` | `x=42` | `x=12345` | 评价 |
| --- | --- | --- | --- | --- |
| 先数位数 `cnt`，再 `pow(10, cnt-1)` | 1 ✓ | 10 ✓ | 10000 ✓ | 对，但先数一遍、还要照顾指数，绕 |
| `while (t > 0) { t /= 10; mask *= 10; }` | **10** ✗ | **100** ✗ | **100000** ✗ | **一律偏大 10 倍** |
| `while (t > 9) { t /= 10; mask *= 10; }` | 1 ✓ | 10 ✓ | 10000 ✓ | **选中** |

⚠️ **校正③**：`while (t > 0)` 偏大 10 倍，**原因不是「初值给成 1」** —— 初值 1 是对的、也是必须的。
真正原因是它**多走了一轮**：`t` 要走到 `0` 才停，而 `mask` 在那之前就已经到顶了。
改成 `t > 9`（`t` 只剩一位就停），正好卡住。

### 阶段 4 · 边界 70000：两个 bug 是**先后**冒出来的

```
输入 70000
  while(x>0)   + if(x>9)      [7 ]          ← 原始版：两个 bug 都在
  while(mask>0) + if(x>9)     [7 0000]      ← 改了循环条件，第二个 bug 才露头
  while(x>0)   + if(mask>9)   [7 ]          ← 只改 if 没用，循环第 1 轮就退了
  while(mask>0) + if(mask>9)  [7 0 0 0 0]   ✓
```

**两个 bug 各有各的后果，别混：**

1. **循环条件 `x > 0`** → 第 1 轮之后 `x` 已经是 `0`，条件立刻不成立，**后面四位根本没进循环**。
   现象：只打出 `7 `（0 一个都没出来）。修法：改 `while (mask > 0)`
2. **`if (x > 9)`** → `x` 已经是 `0`，永远不成立，**几个 0 之间没有空格**。
   现象：`7 0000`。修法：改 `if (mask > 9)`

⚠️ **校正④**：你说的「4 个 0 连在一起」是**第二个** bug 的现象，
它**只有在循环条件已经改好之后**才看得到。原始版（两个都没改）看到的是 `7 `。
「0 不出来」和「0 挤在一起」是**两个独立 bug**，要分开改。

### 阶段 5 · 两处修正其实是同一句话

| 位置 | 老写法 | 改成 | 它管什么 |
| --- | --- | --- | --- |
| `while` 条件 | `x > 0` | `mask > 0` | **还要不要继续取值** |
| `if` 条件 | `x > 9` | `mask > 9` | **这一位后面要不要加空格** |

> **凡是问「还剩几位」，一律问 `mask`，不问 `x`。**
> `x` 会被 `x %= mask` 切碎到 0；`mask` 只跟「第几位」有关，不会被切。

（这就是你复述里那句「mask > 9 等效替代了最开始那个 x > 9」—— 判断对，**原理就在这**。）

### 完整成品

```c
int x;
scanf("%d", &x);

int mask = 1;
int t = x;                        /* 副本，只为算 mask */
while (t > 9) {
    t /= 10;
    mask *= 10;
}

do {
    int d = x / mask;             /* 取当前最高位 */
    printf("%d", d);
    if (mask > 9) printf(" ");    /* 还有下一位才加空格 */
    x %= mask;                    /* 抹掉这一位 */
    mask /= 10;                   /* 尺子降一位 */
} while (mask > 0);
```

成品实测：

```
输入 0        [0]  (mask 起步 1)
输入 7        [7]  (mask 起步 1)
输入 42       [4 2]  (mask 起步 10)
输入 700      [7 0 0]  (mask 起步 100)
输入 12345    [1 2 3 4 5]  (mask 起步 10000)
输入 70000    [7 0 0 0 0]  (mask 起步 10000)
```

### 这节真正值得带走的三件事

1. **改程序 = 拿边界去撞。** `700` 撞出岔路 A 的死穴，`70000` 一次撞出两个 bug。
   都是「随手挑个特殊输入」撞出来的，不是坐着想出来的。
2. **一件事一个变量。** `mask` 记位置、`x` 记数值 —— 这是第六次出现这个原则
   （`sign` / `cnt` / `isPrime` / `found` / `t` 副本 / `mask`）。
3. **一个 bug 修好，常常立刻露出下一个。** 所以在阶段 4 里，
   你不修第一个就永远看不见第二个 —— 不是你改错了，是那一层本来就被挡着。
