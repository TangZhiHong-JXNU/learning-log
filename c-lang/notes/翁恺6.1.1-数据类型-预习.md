## 一、这一节其实只在讲一句话

**C 是有类型的语言。**

拆开就是两个硬性要求 + 三个差别：

| | 内容 |
| --- | --- |
| **两个硬性要求** | ① 变量**使用前必须先定义** ② 定义时必须**指定类型** |
| **三个差别** | ① 类型**名字**不同 ② 输入输出**格式符**不同 ③ 占的**字节数 / 能表示的范围**不同 |

第 6 周整整一周（6.1.1 ~ 6.1.9）都在展开第三个差别。6.1.1 只是把这张地图摊开给你看。

## 二、硬性要求长什么样：实测报错原文

写一句 `a = 6;` 就编译，本机结果：

```
probe4.c: In function 'main':
probe4.c:3:5: error: 'a' undeclared (first use in this function)
     a = 6;
     ^
probe4.c:3:5: note: each undeclared identifier is reported only once
                   for each function it appears in
```

`undeclared` = 「没有声明过」。

**关键在 note 那句**：同一个没声明的名字，一个函数里**只报一次**。
所以如果你写了 10 处 `a`，只会看到第一条错误，改完再编译才看得见下一条 ——
**不是改错了，是后面的被挡着**（和 5.3.2 那两个 bug 的先后关系是同一个道理）。

如果写 `int a = 6;` 再编译，就什么都不报。

> 你在第 2 周写的 `int price = 0;`、`double x;` —— 那时候就在用「类型」了，
> 只是当时没人告诉你这一步叫「确定类型」。

## 三、为什么非得有类型：两边在吵架

| | 强类型 | 弱类型 |
| --- | --- | --- |
| 代表语言 | C、C++、Java | JavaScript、Python、PHP |
| 变量要不要先定义 | **要** | 不用，随手写 |
| 支持方观点 | 把类型说清楚，**简单的错误能在编译时就被抓住** | — |
| 反对方观点 | — | 太强调类型，**逼着程序员去管底层和实现，而不是管业务逻辑** |

翁恺的落点（要记住这一句）：

> **早期语言、面向底层的语言强调类型。**
> **C 需要类型，但对类型的安全检查并不足够。**

最后半句是重点：C 要你写类型，但**它不保证你写对**。
`printf("%d", 3.14)` 这种明显错的东西，编译器只给个 warning，照样跑 ——
这跟 Java 直接编译不过是不一样的。

（顺带一句：C 是**编译型**语言，Java 是**解释型**语言，别混。）

## 四、C 的类型清单（本机实测字节数）

程序：对每个类型 `printf("%d", (int)sizeof(...))`。真实输出：

```
char        = 1 byte        float       = 4 byte
short       = 2 byte        double      = 8 byte
int         = 4 byte        long double = 16 byte
long        = 4 byte        bool        = 1 byte
long long   = 8 byte        int *       = 8 byte
```

| 类型 | 名称 | 格式符 | 本机字节 | 范围 |
| --- | --- | --- | --- | --- |
| 整数 | `char` | `%c` / `%d` | 1 | -128 ~ 127 |
| 整数 | `short` | `%d` | 2 | -32768 ~ 32767 |
| 整数 | `int` | `%d` | 4 | ±21.4 亿 |
| 整数 | `long` | `%ld` | **4** | **和 int 完全一样** |
| 整数 | `long long` | `%I64d` | 8 | ±922 京 |
| 浮点 | `float` | `%f` | 4 | 约 7 位有效数字 |
| 浮点 | `double` | `%f` | 8 | 约 16 位有效数字 |
| 浮点 | `long double` | `%Lf` | 16 | 更宽 |
| 逻辑 | `bool` | `%d` | 1 | 0 或 1（要 `#include <stdbool.h>`） |
| 指针 | `int *` | `%p` | 8 | 一个内存地址 |
| 自定义 | `struct` 等 | — | — | 第 11 周 |

带下划线的三个（`long long`、`bool`、`long double`）是 **C99 才加进来的**，不是 C 从娘胎里带的。

## 五、三种差别里最容易被忽略的那个

名字和格式符是死记的，**真正需要理解的是「为什么 float 和 int 都占 4 字节，却是两种东西」**。

本机实测（两个类型共用一段内存，先写后读）：

```
as float = 3.140000
as uint  = 1078523331
```

同一段 4 个字节 `C3 F5 48 40`：

- 按 `float` 的规则解析 → `3.140000`
- 按 `unsigned int` 的规则解析 → `1078523331`

**字节一个都没动，换个类型就是另一个数。**

所以「类型」这件事的完整含义是两层：

1. 决定这段内存**占几个字节**（格子数量）
2. 决定这堆比特**按什么规则翻译**（格子怎么读）

第 2 层是第 6 周后半（整数的补码、浮点的编码）要展开的，先有个印象。

## 六、sizeof：量格子数量的那把尺子

写法 `sizeof(类型)` 或 `sizeof(变量)`，**结果是它占的字节数**。

### 它不是函数，是运算符

所以 `sizeof(int)` 的括号是「运算符的括号」，跟 `printf` 的函数括号不是一回事。

### 它是「静态运算符」——括号里的东西根本不会被执行

本机实测（这一条是这节最值得自己动手验的）：

```c
int i = 0;
printf("sizeof(i++) = %d,  i after = %d\n", (int)sizeof(i++), i);
printf("sizeof(1/0)   = %d\n", (int)sizeof(1 / 0));
```

真实输出：

```
sizeof(i++) = 4,  i after = 0
sizeof(1+2*3) = 4
sizeof(1/0)   = 4
```

两处证据：

- `sizeof(i++)` 算出 4，但**运行完 `i` 还是 0** —— 那个 `++` 压根没执行
- `sizeof(1/0)` 算出 4，**程序没崩、编译连 warning 都没有** —— 因为压根没做除法

（`1/0` 一旦真的运算，程序会被 CPU 打断报错。它没报，就说明 `sizeof` 只看了它一眼、算了个类型大小就完事了。）

> **一句话**：`sizeof` 只关心「括号里是什么类型」，不关心「括号里等于几」。

## 七、跟视频敲的时候，必踩的两个坑

视频是在 Linux / Mac 上录的，Windows 上有两处不一样。**这两条是本机实测的，不是猜的。**

### 坑 1：视频里的 `%ld` 打印 `sizeof`，本机一直刷警告

视频里常写：

```c
printf("sizeof(int)=%ld\n", sizeof(int));
```

本机编译结果（warning，不是 error，程序照样跑）：

```
warning: format '%ld' expects argument of type 'long int',
         but argument 2 has type 'long long unsigned int' [-Wformat=]
```

原因：本机 `sizeof` 返回的类型是 **8 字节的无符号整数**（`long long unsigned int`），
而 `%ld` 声明「我只要 4 字节的 `long`」。俩对不上。

实际跑出来数字**是对的**（4 和 8 都印对了），但这是**侥幸**，属于未定义行为。

**本机的干净写法**：先转成 `int` 再打印 ——

```c
printf("sizeof(int)=%d\n", (int)sizeof(int));
```

（新一些的 gcc 可以用 `%zu`，但本机 4.9.2 **不认识 `%zu`**，会报
`unknown conversion type character 'z'`。所以统一用 `(int)` + `%d` 最省事。）

### 坑 2：`long long` 用什么格式符

本机实测四种写法：

| 写法 | 编译警告 | 运行结果 |
| --- | --- | --- |
| `%lld` | **有**（`unknown conversion type character 'l'`） | 数字对 |
| `%I64d` | **没有** | 数字对 |
| `%llu` | 有 | 数字对 |
| `%I64u` | 没有 | 数字对 |

结论：**本机用 `%I64d` / `%I64u`**（MS 系方言），视频里的 `%lld` 能跑但会一直刷警告。

### 附带一条：`long` 在 Windows 上和 `int` 一样大

很多资料说「`long` 比 `int` 长」，在**本机不成立** —— 两个都是 4 字节。

所以第 6 周看到 `long` 的时候别慌，本机用不到它；真需要超过 21 亿的数，直接用 `long long`。

## 九、这一节和你已经会的东西怎么接上

| 你已经会的 | 6.1.1 给它起了名字 |
| --- | --- |
| `int price = 0;` | 定义 + 确定类型 + 初始化 |
| `scanf("%d", &price);` | `%d` 对应 `int`（格式符是类型的一部分） |
| `printf("%.1f", x);` | `%f` 对应 `double` |
| `100 - price` | 同类型才能直接运算 |
| 3.14 写成 `3.0` 让除法变浮点 | **类型不同 → 结果不同**，这就是本节的中心思想 |

**你不是从零开始学类型，你是回头给已经用过的东西补名字。**
