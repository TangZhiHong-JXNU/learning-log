# 翁恺 4.3.3 整数的反转 · 逐步拆解

## 一、这节课到底在解决什么问题

输入一个正整数，比如 `1234`，输出它的倒过来 `4321`。

- **分解思路**：不拆字符串，纯靠算术。
- **核心循环次数**：整数有几位，就循环几次。位数 = 每次 `n = n / 10` 直到 `n` 变成 0 的次数。

---

## 二、三个必备运算符（先确认你真的懂）

| 运算符 | 作用 | 例子 | 口诀 |
|---|---|---|---|
| `%` | 取余，保留**除不尽**的那部分 | `1234 % 10 = 4` | 拿末位 |
| `/` | 整除，**丢掉**除不尽的部分 | `1234 / 10 = 123` | 砍末位 |
| `* 10` | 腾出一个末位的位置 | `4 * 10 = 40` | 拼位用 |

关键认知：
- `1234 % 10` 之所以是 4，是因为 `1234 = 123 × 10 + 4`，余数 4 就是末位。
- `1234 / 10` 之所以是 123，是因为整数除法**直接把余数扔了**。
- 所以 `%10` 和 `/10` 是一对"镜像操作"：一个留末位，一个去末位。

---

## 三、为什么结果要 `rev = rev * 10 + digit`

假设已经处理了 `123`，`rev` 现在是 `123`。接下来要处理末位 `4`，希望 `rev` 变成 `1234`。

- 直接写 `rev = rev + digit` → `123 + 4 = 127` ❌ 变成 127 了，4 跑到个位，位置错了
- 写 `rev = rev * 10 + digit` → `123 * 10 + 4 = 1234` ✅

**`rev * 10` 的作用是把 rev 整体往左挪一位（腾出个位），然后 `+ digit` 把新数字填进这个个位。**

这就是"十进制逐位构造"的技巧：每来一个新数字，就把它乘 10 顶到前面。

---

## 四、完整手算过程（务必自己在纸上算一遍）

输入 `n = 1234`，`rev` 初始为 `0`（因为要用 `rev * 10`，必须从 0 起步，0 乘任何数还是 0）

| 轮次 | 进入时 n | digit = n % 10 | rev = rev*10 + digit | 之后 n = n / 10 |
|---|---|---|---|---|
| 1 | 1234 | 4 | 0*10+4 = **4** | 123 |
| 2 | 123  | 3 | 4*10+3 = **43** | 12 |
| 3 | 12   | 2 | 43*10+2 = **432** | 1 |
| 4 | 1    | 1 | 432*10+1 = **4321** | 0 |

第 4 轮后 `n = 0`，`while (n != 0)` 判断失败，循环结束，输出 4321。

**对照检查口诀**：`rev` 里的数字顺序，正好是原数从右往左读出来的顺序。

---

## 五、代码骨架（先自己默写一遍，卡住再看）

```c
#include <stdio.h>

int main(void) {
    int n, rev = 0, digit;   // rev 必须初始化为 0

    scanf("%d", &n);

    while (n != 0) {         // 条件：还有位没处理
        digit = n % 10;      // 第1步 拆末位
        rev = rev * 10 + digit;  // 第2步 拼到结果
        n = n / 10;          // 第3步 砍末位
    }

    printf("%d\n", rev);
    return 0;
}
```

### 逐行对照表

| 行 | 作用 | 容易错的地方 |
|---|---|---|
| `int n, rev = 0, digit;` | 声明三个变量 | 只有 `rev` 初始化了，`n` 必须等你 scanf |
| `scanf("%d", &n);` | 读入待反转的数 | `&` 不能漏 |
| `while (n != 0)` | 循环条件 | 写成 `while (n)` 也对（C 里非 0 为真），但 `!= 0` 更表意 |
| `digit = n % 10;` | 取末位 | 分号不能漏 |
| `rev = rev * 10 + digit;` | 拼接 | 顺序不能写成 `rev * 10 + n` |
| `n = n / 10;` | 去掉末位 | 这一步放在最后，放前面就死循环 |
| `printf("%d\n", rev);` | 输出 | 循环外，不在 `{}` 里 |

```c
printf("n=%d digit=%d rev=%d\n", n, digit, rev);
```

## 七、常见报错对照

| 报错 / 现象 | 真实原因 |
|---|---|
| `expected ';' before 'n'` | 上一行末尾漏了分号 |
| 输出死循环 / 不停 | `n = n / 10;` 写成了 `n %= 10;`（% 不改变 n，永远不为 0） |
| 输出恒为 0 | `rev` 没初始化，或 `rev * 10` 写成了 `rev + 10` |
| 输出正序 1234 | `rev = rev * 10 + digit` 写反了顺序 |
| **输入 1234 输出 100** | 写成 `rev = digit * 10 + rev` —— **`*10` 乘错对象了**（见下方专条） |
| `while (n != 0);` | 多写了分号，循环体变成空语句 |

### 专条：`rev = digit * 10 + rev` 为什么得到 100（真实踩坑 2026-10-04）

错误写法把 `*10` 加在了新位身上，而不是旧结果身上。逐轮演算：

| 轮 | digit | 错误算法 `digit*10+rev` | 正确算法 `rev*10+digit` |
|---|---|---|---|
| 1 | 4 | 4*10+0 = **40** | 0*10+4 = **4** |
| 2 | 3 | 3*10+40 = **70**（40 被顶掉） | 4*10+3 = **43** |
| 3 | 2 | 2*10+70 = **90** | 43*10+2 = **432** |
| 4 | 1 | 1*10+90 = **100** | 432*10+1 = **4321** |

**记忆法**：`*10` 是"把已经攒好的旧结果整体左移一位"的动作，
所以**只能乘在 `rev` 上**；`digit` 是新来的个位，它不需要移位，直接加进去。

口诀：**旧的整体挪，新的填末尾 → `rev = rev*10 + digit`。**

对照检查：如果算出来是 `100` / `70` / `90` 这种"末尾带零、位数还变少"的数，
基本就是 `*10` 加错对象了。

## 七点五、追问：如果 700 要变成 007 呢？（重要分界线）

### 为什么拼不出来

`700` 拆位是 `0, 0, 7`：

| 轮 | digit | rev = rev*10 + digit |
|---|---|---|
| 1 | 0 | 0*10+0 = 0 |
| 2 | 0 | 0*10+0 = 0 |
| 3 | 7 | 0*10+7 = 7 |

**前导的 0 乘出来还是 0，被吃掉了。** 因为 `int` 存的是**值**不是**写法**：
`7`、`007`、`7.0`、`0x7` 是同一个值，变量里根本无法区分。
→ **"007" 本质不是数，是一串字符。**

### 三条路，怎么选

**路线 A：不拼数，拆一位打一位（推荐，PAT 标准解法）**

三位数逆序根本不用循环：

```c
int n;
scanf("%d", &n);
printf("%d%d%d", n % 10, n / 10 % 10, n / 100);
```

`700` → 打印 `0`、`0`、`7` → 输出 `007` ✅
关键：这是**打印三个字符**，不是算一个数，所以前导零天然保留。

**路线 B：拼出 rev 后补零**

```c
printf("%03d\n", rev);   // rev=7 → 007
```

`%03d` = 至少 3 位，不足左边补 0。
**边界**：宽度写死了。若输入 `1200` 想得到 `0021`（4 位），得改成 `%04d`。
**位数不固定的题这条路就废了**，必须回路线 A。

**路线 C：字符串存原样**（学完字符数组再说）
输入本来就是 `'7' '0' '0'` 三个字符，倒着打天然是 `007`。

### 一句话记忆

> 要"值"用 int，要"样子"用字符。
> 题目说"反转后的数"→ 700 得 7；题目说"输出逆序的数字/字符串"→ 才讨论 007。
> **拿不准时看样例**：样例输出写 `7` 就别补零，写 `007` 就得走路线 A。

### 变体 3 的答案：负数怎么办（2026-10-04 他自己推出 + 实测）

**实测：直接拿原代码跑 `-1234`，输出 `-4321`。**（他没改一行代码）

| 轮次 | digit = n%10 | rev = rev*10 + digit | n = n/10 |
|---|---|---|---|
| 1 | **-4** | 0*10+(-4) = **-4** | -123 |
| 2 | **-3** | -4*10+(-3) = **-43** | -12 |
| 3 | **-2** | -43*10+(-2) = **-432** | -1 |
| 4 | **-1** | -432*10+(-1) = **-4321** | 0 |

**为什么能work —— `%` 和 `/` 对负数是"配套设计"的：**

```
-1234 % 10 = -4     ← 余数带负号
-1234 / 10 = -123   ← 商向 0 截断（-123.4 → -123，不是 -124）
```

两者必须满足铁律：**商 × 除数 + 余数 = 被除数**
`(-123) × 10 + (-4) = -1234` ✓ → 余数**必须**带负号，否则凑不出原数。

**⚠️ 边界（这里最容易翻车）：**
- C89 对负数除法**未做规定**，可能给出 `-4` 也可能 `6`；
  **C99 起才强制统一为"向 0 截断"**。本项目编译带 `-std=c11`，所以行为固定。
- 换成不指定标准的老编译器 → 结果可能完全不同。
- PAT 题一般**避开负数**或明说"输入正整数"，就是为了躲这个坑。

**稳妥写法（不依赖巧合）：**

```c
int sign = 1;
if (n < 0) { sign = -1; n = -n; }   // 先记符号，转正
// ... 原反转循环 ...
printf("%d\n", sign * rev);          // 最后补回负号
```

**原则**：代码里靠"运算符的隐式规则恰好成立"的逻辑，是以后出错的高发区；
显式写出来（先转正、后补符号）别人一眼能看懂。



### 变体 1 的答案（2026-10-04 他自己推出来的）

`1200` 的逐轮过程（gcc 实测）：

| 轮次 | digit = n%10 | rev = rev*10 + digit | n = n/10 |
|---|---|---|---|
| 1 | 0 | 0*10+0 = **0** | 120 |
| 2 | 0 | 0*10+0 = **0** | 12 |
| 3 | 2 | 0*10+2 = **2** | 1 |
| 4 | 1 | 2*10+1 = **21** | 0 |

最终 `21`。

**关键纠正（他自己说的"第三步才消失"要再精确一点）**：
不是"第 3 步才消失"，而是 **0 从来没进到 rev 里去过**。

> **`0` 加到 `rev` 上等于没加 —— `rev*10` 只有在 `rev` 非 0 时才"腾位子"；
> `rev` 是 0 时 `0*10 = 0`，原地不动。`int` 里的前导零不占位。**

推论：**原数末尾有多少个 0，反转后就有多少个前导 0，然后全被吃掉。**
所以 `700 → 7`、`1200 → 21`。

想要 `1200 → 0021` 这种带前导零的输出，只能走 §7.5 的**路线 A**（逐位 printf，不拼数）。
