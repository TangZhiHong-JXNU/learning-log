> 2026-10-04 晚。他从"思路有、程序图写不出来"开始，自己推出了全部结构。
> 本笔记记录推导过程 + gcc 实测数据 + 四个坑。

## 一、这节课只有一个新东西：嵌套循环

**一个循环，套在另一个循环里面。**

| 层 | 干什么 | 类比 |
|---|---|---|
| **外层** | 挨个数：`n` 从 2 走到 100 | 考官，一个个念考生名字 |
| **内层** | 判断这一个数是不是素数 | 判卷，对每个考生做一遍同样的检查 |

> 他那句原话——"**每个数都要进入一个循环**"——就是嵌套循环的定义。

### 核心思维转变

要把"打印 100 以内的素数"理解成：

> **把已经写好的"判断一个数是不是素数"当成一块积木，整块塞进另一个循环里，重复用 99 次。**

不需要新算法，只需要**再拿一个循环把原来那段包起来**。

## 二、骨架（大盒子套小盒子）

```c
int n, i, isPrime;          /* ① 定义：整个程序只做一次 */

for (n = 2; n <= 100; n++) {     /* 外层：挨个数 */
    isPrime = 1;                 /* ② ★ 每轮必须重来一次的初始化 */
    for (i = 2; i < n; i++) {    /* 内层：判断这一个（一个字都不用改） */
        if (n % i == 0) { isPrime = 0; break; }
    }
    if (isPrime) printf("%d ", n);   /* ③ 结论没被推翻 → 打印 */
}
```

**位置决定频率**：
- ① 在循环**外面** → 只执行一次
- ② ③ 在循环**里面** → 每一轮都执行一次

## 三、★ 那一格为什么必须是"重置"？

三个变量里，只有 `isPrime` 没人管：

| 变量 | 谁在每轮给它重新赋值 | 要手写吗 |
|---|---|---|
| `n` | `n++`（for 第三格） | 不用 |
| `i` | `i = 2`（for 第一格，每轮进内层都执行） | 不用 |
| **`isPrime`** | **没有人** | **★ 就是给它用的** |

> **`i` 每轮被 `for` 头部自动重置成 2；`n` 每轮被 `n++` 更新；
> 只有结论变量是"裸"的——它上一轮被写坏过，下一轮带着旧值进来。**

### 实测：把 ★ 挪到外层循环外面会怎样

```c
isPrime = 1;                       /* ← 只在这里设一次（错） */
for (n = 2; n <= 100; n++) {
    for (i = 2; i < n; i++) if (n % i == 0) { isPrime = 0; break; }
    if (isPrime) printf("%d ", n);
}
```

输出：**`2 3`** —— 只剩 2 个（正确是 25 个）。

原因：处理 `n = 4` 时 `isPrime` 被改成 0，**从此再也没人把它改回来**，
5、7、11……97 全被吞掉。程序不报错，只是数字少了一大半。

> 这跟 5.2.1 §十一"初值 = 什么都没发生时的默认答案"是同一条，
> 只是升了一级：**从"初值是什么"升级到"初值在哪儿重置"。**

### "重置"到底是什么意思

**重置 = 把格子里的旧值擦掉，重新写一个干净的值。**

它不是新语法，只是一个普通的赋值语句。特殊之处在**位置**：

| 动作 | 写在哪 | 执行频率 |
|---|---|---|
| 定义 `int isPrime;` | 函数开头 | **整个程序 1 次** |
| 重置 `isPrime = 1;` | 外层循环体**里面** | **每轮 1 次** |

**为什么变量会"带着脏值"进下一轮？** 因为变量的寿命 = 它所在的那对 `{ }`，
外层循环体在 `main` 的 `{ }` 里面，所以 `isPrime` 活过了每一轮。
C 不会自动帮你归零——**变量只在定义时被赋一次值，之后全靠你。**

> 一句话：**变量不是"每轮出生一次"，是"一次出生，反复改值"。**
> 这跟 §四"变量是格子，不是数"是同一条，只是从"值会被改"推到"值会被留下"。

### 判据：两类变量，两条规则

同一段代码里两类变量共存：

| 类型 | 例子 | 要不要重置 | 依据 |
|---|---|---|---|
| **跨轮累积** | `sum`、`result`、`cnt` | **不重置** | 这一轮要接着上一轮的成果算 |
| **每轮独立** | `isPrime`、`sign` | **必须重置** | 这一轮的结论与上一轮毫无关系 |

> **判据一句话：这一轮的值，需不需要用到上一轮的值？**
> 需要 → 累积型，别清；不需要 → 独立型，每轮清干净。

这就是为什么你写平均数、阶乘、前 50 个素数时从来没想过重置——
`sum / result / cnt` 全在第一类，**它们的"记得上一轮"正是设计意图**。
`isPrime` 是第一次遇到第二类。

### 重置的两种写法（都对）

| 写法 | 长什么样 | 特点 |
|---|---|---|
| A 手动重置 | 声明在外 + 循环体**第一行** `isPrime = 1;` | 一眼看得见"我重置了" |
| B 声明在循环内 | `int isPrime = 1;` 写在循环里 | 自动重置，想忘都忘不掉（翁恺版，见 §十.7） |

**危险的是半成品**：声明在外、又忘了写重置 → 就是上面"只剩 `2 3`"的坑。

### 放在哪一行

**循环体的第一行**（尽可能靠前）。理由：越早写越不会被后面的语句影响，
万一以后往循环体里加 `continue`，写在最前面也一定执行得到。

### 边界：什么时候根本不用想重置

1. **只有一层循环**（如 5.2.1 只判断一个数）→ 没有"上一轮"，谈不到重置
2. **变量只在一轮里活着** → 同理不需要
3. 所以**重置是"多轮循环"才出现的问题**，不是每道题都要想的动作

## 四、"`i` 只有一个，够吗？"——变量不是数，是格子

他的原疑问："判断 100 个数，是不是要定义 100 个变量？"

**不用。变量是一个格子，值被反复擦掉重写。**

实测（内层里 `i` 走过的值）：

```
外层 n = 3   内层: i=2
外层 n = 4   内层: i=2 i=3
外层 n = 5   内层: i=2 i=3 i=4
外层 n = 6   内层: i=2 i=3 i=4 i=5
```

**每行都以 `i=2` 开头** → `i` 不记忆上一轮的进度，每轮进内层都被 `for` 头部重置。

实测总量（2 到 100）：

| 项目 | 数值 |
|---|---|
| 判断的数的个数 | 99 |
| 内层循环体执行次数 | **1133 次** |
| 用掉的 `i` 的个数 | **1 个** |
| 找到的素数个数 | **25** |

> **1133 次运行，1 个变量。** 类比：喝 100 杯水不需要 100 个杯子——一个杯子，喝完洗了再装。

## 五、外层从 2 开始，不能从 1 开始（实测）

| 写法 | 输出 | 个数 |
|---|---|---|
| 甲 `for (n = 1; ...)` | **`1` 2 3 5 7 … 97** | **26 个 ✗** |
| 乙 `for (n = 2; ...)` | 2 3 5 7 … 97 | 25 个 ✓ |
| 丙 从 1 开始 + `if (n < 2) continue;` | 2 3 5 7 … 97 | 25 个 ✓ |

**为什么 1 会被打印成素数**：内层 `for (i = 2; i < 1; i++)` **一次都不跑**，
`isPrime` 停在初值 1，结论"没被推翻" → 打印。

> 注意：1 被误判**只发生在"标志变量"这条路线上**。
> 5.2.1 的 `i == n` 路线反而会自动判对（`i` 停在 2 ≠ 1）——那是巧合，别依赖。

**两种修法**：
- 简单：外层直接从 2 开始（本节的题就够用）
- 稳：开头特判 `if (n < 2) continue;`（以后 n 不固定时要用这种）

## 六、内层计数器的名字不能也叫 `n`（实测：死循环）

```c
for (n = 2; n <= 100; n++) {
    isPrime = 1;
    for (n = 2; n < 10; n++) {     /* ← 手滑：内层也用了 n */
        if (n % 2 == 0) { isPrime = 0; break; }
    }
    ...
}
```

实测结果：`n` 每一轮结束都停在 **2**，外层永远前进不了 → **死循环**（我加保险计数器才跑完）。

**原因**：内层把 `n` 重置成 2，外层 `n++` 刚加到 3 又被内层拉回 2。

> **一条铁律**：**外层和外层、内层和内层，各自一套变量名；两层之间绝不共用。**
> 这是"一件事一个变量"的第 4 次出现（前三次：sign 的符号/数值、阶乘的 n/i、素数的循环控制/结论）。

## 十、进阶 try：打印**前 50 个**素数（上限未知）

### 1. 题目变了什么：从"边界已知"到"边界未知"

| 题目 | 循环到哪儿停 | 条件写什么 |
|---|---|---|
| 打印 100 以内的素数 | **n 到 100** | `n <= 100` |
| 打印**前 50 个**素数 | **不好说 n 是几**（实际要到 **229**） | `cnt < 50` |

> **不能靠"猜一个够大的上限"来解决问题**——猜小了凑不满 50 个，
> 猜大了又停不下来。正确做法是把"什么时候停"这件事，**交给一个计数器**。

这就是"**计数控制循环**"（循环次数事先未知，跑到数够为止）。
和 for 那种"次数已知"的循环是一个分界。

### 2. 骨架（只改了循环头 + 加一个计数器）

```c
int n, i, isPrime, cnt = 0;          /* cnt：已经打印了几个素数 */

for (n = 2; cnt < 50; n++) {         /* ← 条件从 n 换成了 cnt */
    isPrime = 1;
    for (i = 2; i < n; i++)
        if (n % i == 0) { isPrime = 0; break; }
    if (isPrime) { printf("%d ", n); cnt++; }   /* ← 只有"确实是素数"才计数 */
}
```

**和上一版比，只动了两处**：
1. `n <= 100` → `cnt < 50`（**边界搬家了**）
2. `if (isPrime) printf(...)` → 后面补一个 `cnt++`

### 3. 实测三种写法（gcc）

| 写法 | 结果 | 结论 |
|---|---|---|
| 甲 `cnt < 50` + `cnt++` 在 `if` **里** | 2 3 5 … 227 **229**，共 **50 个** | ✓ |
| 乙 `cnt < 50` + `cnt++` 在 `if` **外面** | 打到 **47** 就停了（只有 15 个） | ✗ |
| 丙 保持 `n <= 100` 不改循环头 | 只有 **25 个** | ✗ 凑不满 |

**乙为什么会错**：`cnt++` 写在 `if` 外面 = **见一个数就数一个**，
数到 50 时 n 才 51 → 只试除到 51 就收工了，素数当然只打到 47。

> **`cnt` 只准数素数。写在 `if (isPrime)` 里面，是它的唯一合法位置。**

### 4. 自检数据

- **第 50 个素数 = 229**
- 循环**退出时 `n = 230`**（因为 `n++` 在条件判断之前先执行了一轮）

| 排名 | 第10 | 第20 | 第30 | 第40 | 第50 |
|---|---|---|---|---|---|
| 素数 | 29 | 71 | 113 | 173 | **229** |

### 5. 一句话对照

> **"100 以内"看 `n`，"前 50 个"看 `cnt`。**
> 边界跟着"题目的约束"走，不是跟着某个固定的数走。
>
> 这也是"一件事一个变量"的又一次落地：`n` 负责"挨个数"，
> `cnt` 负责"数到几个了"——**两件事，两个变量，互不干扰。**

### 6. 两个一格的细节（他自己答出来的，配 gcc 实测）

他自己答的是 `for (n = 2; cnt <= 50; n++)`，`cnt++` 放 `if` 外面。**两处各差一格。**

**先记一句定义，两处细节都从它推出来：**

> **`cnt` 的含义 = "已经数出了几个素数"。**
> 一旦接受这个含义，下面两处自动有答案，不用背。

**细节①：`<=` 还是 `<`？**（他写的是 `<=`）

| 条件 | 打出几个 | 最后一个 | 结论 |
|---|---|---|---|
| `cnt < 50` | **50 个** | **229** | ✓ |
| `cnt <= 50` | **51 个** | **233** | ✗ 多打 1 个 |

原因：`cnt` 从 0 起，每找到一个素数才 +1。**`cnt == 50` 时"已经够了"，
所以那一轮必须被挡住 → 条件写 `< 50`。**

> **通用口诀：计数器从 0 开始、每完成一件 +1 → 条件写 `< 目标数`。**
> （跟数组下标 `0 .. n-1` 是同一个道理，以后到处会撞见。）

**细节②：`cnt++` 在 `if` 里面还是外面？**（他先答了"外面"，实测错）

逐行追踪 `n = 2` 到 6：

| n | isPrime | `cnt++` 在 **if 里** | `cnt++` 在 **if 外** |
|---|---|---|---|
| 2 | 1 | cnt = 1 | cnt = 1 |
| 3 | 1 | cnt = 2 | cnt = 2 |
| 4 | **0** | **cnt 不动 = 2** | **cnt = 3 ← 也数了** |
| 5 | 1 | cnt = 3 | cnt = 4 |
| 6 | **0** | **cnt 不动 = 3** | **cnt = 5 ← 也数了** |

- 写在 `if` 外面 = **见一个数就记一笔**（不管它是不是素数）
- 于是数到 `cnt = 50` 时，`n` 才 51 → 真正打印的素数只有 **15 个**（2 … 47）
- **一行代码在 `{ }` 里面还是外面，决定它"有没有资格执行"。**

**正确写法**：

```c
if (isPrime) { printf("%d ", n); cnt++; }   /* 打印和计数，一起放 if 里面 */
```

### 7. 翁恺视频原版写法 vs 本节写法（实测输出完全一致）

课程流传版本（`while` + **在循环里声明** `isPrime`）：

### 逐行中文注释版

```c
#include <stdio.h>                  /* 要用 printf，必须先包含这个头文件 */

int main() {
    int x = 2;                      /* 从 2 开始挨个数（1 不是素数，直接从 2 起步） */
    int cnt = 0;                    /* 计数器：已经找到几个素数了，初值必须是 0 */

    while (cnt < 50) {              /* 找够 50 个就停 —— 边界看 cnt，不看 x */

        int i;                      /* 试除用的除数；每轮进循环重新出生，从 2 起 */
        int isPrime = 1;            /* 结论变量：先假设"它是素数"（声明在循环里 = 每轮自动重置） */

        for (i = 2; i < x; i++) {   /* 拿 2、3、4 … x-1 一个一个去试除 */
            if (x % i == 0) {       /* 除得尽 → i 是 x 的因子 → 找到反例 */
                isPrime = 0;        /* 推翻"是素数"这个假设 */
                break;              /* 已经有答案了，不必再试，跳出内层循环 */
            }
        }                           /* 这里故意没有 else —— "除不尽"只是没找到证据，不是结论 */

        if (isPrime == 1) {         /* 假设没被推翻 → 它确实是素数 */
            printf("%d ", x);       /* 打印出来 */
            cnt++;                  /* 计数 +1（只有真素数才配数） */
        }

        x++;                        /* 换下一个数往前走（不管是不是素数都要前进） */
    }

    printf("\n");                   /* 收尾换行 */
    return 0;
}
```

**读这段代码的顺序建议**：先看 `while (cnt < 50)`（什么时候停）→
再看 `for` + `if`（怎么判断一个数）→ 最后看 `if (isPrime == 1)`（怎么记账）。

### 四处差异对照

两版共四处不同，**全是"写法"不同，不是"结果"不同**：

| # | 翁恺版 | 本节写法 | 说明 |
|---|---|---|---|
| ① | `while (cnt < 50)` + 末尾 `x++` | `for (n = 2; cnt < 50; n++)` | 等价（for 是把 while 的三件事收进头部，见 5.1.1 笔记） |
| ② | `int isPrime = 1;` 写在**循环里** | 声明在外 + 循环里手写 `isPrime = 1;` | **等价**——循环里声明 = 每轮新建一个，天然重置 |
| ③ | 变量叫 `x` | 变量叫 `n` | 只是名字 |
| ④ | `if (isPrime == 1)` | `if (isPrime)` | 结果一样 |

> **第 ② 条最值钱**：上一节"★ 为什么必须重置"，有两种解法——
> **A. 声明在外面，每轮手写 `isPrime = 1;`**（本节）
> **B. 直接把 `int isPrime = 1;` 写在循环体内**（翁恺版，自动重置）
> B 更省心、更不容易忘，但要求你知道"C 里变量的作用域是它所在的那对 `{ }`"。
> 两种都行；**关键是别写成 A 的半成品——声明在外又不重置**（那就是上节 §三 只剩 `2 3` 的那个坑）。
>
> 另外注意：翁恺版把 `int i;` 和 `int isPrime = 1;` 都写在循环里，
> 所以这两句话**每一轮都重新执行一次**——又一次印证"位置决定频率"。

### 8. 翁恺版（`while`）的执行次序 —— 一套读法

（2026-10-05 他反馈"翁恺这个循环顺序还是有点乱"，于是把每一句的执行次序编了号。）

**为什么 `while` 版看着比 `for` 版乱**：`for` 把三件事挤在头部一行；`while` 把它们拆到三个地方。
**位置不同，执行顺序完全一样** —— 因为 `for` 的"步进"本来也是在循环体跑完之后才执行的。

| 三件事 | `for` 版写在哪 | 翁恺 `while` 版写在哪 |
|---|---|---|
| 初始化 | `for (n = 2; …` | 循环**前面**：`int x = 2;` |
| 条件 | `for (…; cnt < 50; …)` | `while (cnt < 50)` |
| 步进 | `for (…; …; n++)` | 循环体**最后一行**：`x++;` |

**一轮走完的次序（① ~ ⑫）**

| # | 代码 | 说什么 |
|---|---|---|
| — | `int x = 2;` `int cnt = 0;` | 循环之前，只做一次 |
| ① | `while (cnt < 50) {` | 每轮先来这儿问：够 50 个了吗？ |
| ② | `int i;` | 新一轮开始，`i` 重新出生 |
| ③ | `int isPrime = 1;` | 先假定"它是素数"（写在循环里 = 自动重置） |
| ④ | `for (i = 2; i < x; i++)` | 拿 2、3、4 … 挨个试除 |
| ⑤ | `if (x % i == 0)` | 除得尽 → 找到因子 |
| ⑥ | `isPrime = 0;` | 推翻假设 |
| ⑦ | `break;` | 跳出内层，不必再试 |
| ⑧ | `if (isPrime == 1)` | 假设还活着吗？ |
| ⑨ | `printf("%d ", x);` | 打印它 |
| ⑩ | `cnt++;` | 记账 +1（只有真素数才走这行） |
| ⑪ | `x++;` | 这轮结束，换下一个数（不管是不是素数） |
| ⑫ | `}` | **回到 ① —— 唯一的回头路** |

**第二条乱源：这里其实是两条线，不是一条**

| 变量 | 每轮怎么变 | 写在哪 |
|---|---|---|
| `x` | **一定 +1** | 循环体最后，`if` **外面**（⑪） |
| `cnt` | **只有打印时才 +1** | `if (isPrime == 1)` **里面**（⑩） |

→ 所以"循环什么时候停"**只由 `cnt` 决定，跟 `x` 毫无关系**。
（`for` 版里 `n++` 和 `cnt < 50` 并列在头部，反而容易误以为条件只跟 `n` 有关。）

**嵌套的顺序一句话**：外层走一轮 → 内层 `for` **跑完整圈** → 才回到外层记账（⑧⑨⑩）和推进（⑪）。

**三遍读法**（按这个顺序看，不要从上往下逐行硬读）：

1. 先看 `while (cnt < 50)` → **什么时候停**
2. 再看 `for` + `if` → **怎么判断一个数**
3. 最后看 `if (isPrime == 1)` 和 `x++` → **怎么记账、怎么往前走**

## 十一、为什么内层的 `if` 后面不写 `else`？

（2026-10-04 他的提问："为什么翁恺版这里没有用 else if，还是其实它已经等价了？"）

被问的是这两处：

```c
for (i = 2; i < x; i++) {
    if (x % i == 0) { isPrime = 0; break; }   /* ← ① 内层：后面没有 else */
}
if (isPrime == 1) {                           /* ← ② 外层：后面也没有 else */
    printf("%d ", x);
    cnt++;
}
```

**两处答案不一样。**

### ① 内层：不是"等价"，是"不能加"

补成 `else { isPrime = 1; }` 后 gcc 实测追踪：

| x | 类型 | 追踪结果 |
|---|---|---|
| 7 | 素数 | `i=2 → 1→1`、`i=3 → 1→1`、`i=4 → 1→1`、`i=5 → 1→1`、`i=6 → 1→1` |
| 6 | 合数 | `i=2 → 1→0`，**break 直接跳出，else 一次都没轮到** |

**为什么 else 是空操作：**

1. **合数**：`if` 成立 → 赋 0 并 `break` → **跳出循环，else 永远轮不上**
2. **素数**：`if` 从头到尾不成立 → 只能走 else → 可没 break 过就说明 `isPrime` 一直是初值 1
   → 于是 `isPrime = 1;` 就是**把 1 写成 1**

**三版对撞（实测 2~500）：**

| 写法 | 结果 |
|---|---|
| A 无 `else`（翁恺版） | 正确 |
| B 有 `else` + 保留 `break` | 与 A **完全一致**（纯空操作，白写） |
| C 有 `else` + 去掉 `break` | **全部判成素数** ✗ |

C 崩掉的原因：`x = 6` 时 `i=2` 写成 0、`i=3` 还是 0，
可 `i=4`（4 不是因子）走 else 又被写回 1 —— **"没找到因子"把"找到因子"的证据抹掉了**。

> 内层那句 `if` 表达的是"**找到反例就定罪**"，
> 而"没找到"**不构成任何结论**——它只意味着"继续试下一个 i"。
> 给一个不存在的结论配 else，要么是废话，要么是灾难。

### ② 外层：确实等价（空 else）

`if (isPrime == 1) { ... }` 后面省掉 else，**逻辑上完全等价**——
因为 else 分支是"什么都不做"，而"什么都不做"本来就是默许的。
写一个空 `else { }` 只是噪音。

### 什么时候真的需要 else

判据一句话：**另一种情况，你有话说吗？**

| 情况 | 要不要 else |
|---|---|
| 另一种情况没事可做（本例外层） | **不要**——空 else 是噪音 |
| 另一种情况的处理已经写在别处（`isPrime = 1` 初值） | **不要**——写了是重复 |
| 另一种情况也有动作 | **必须写** |

第三种的样子：

```c
if (a[i] == target) found = 1;
else                cmp++;        /* 两个分支都要干活 */
```

### 顺便：`else if` 是另一回事

`else if` 是**多分支链**，用在"三档以上"：

```c
if (score >= 90)      grade = 'A';
else if (score >= 60) grade = 'B';
else                  grade = 'F';
```

素数判断只有**两档**（是 / 不是），`if` 就够了，
**没有第三档可判**——所以这里根本谈不到 `else if`。

### 一句话收束

> **`else` 不是 `if` 的标配。它是"另一种情况我也有话说"时才付的钱。**

## 十二、`break` 和 `else if` 之间有因果关系吗？

（2026-10-04 他的追问："即使有 break，如果我写了 else if，还会进到 else if 里面吗？"）

**答案：不会。但原因不是 break，是"if 已经成立了"。**

gcc 实测（内层写成 `if ... else if (i == 3) ... else`）：

| 情况 | `if` 进了几次 | `else if` 进了几次 |
|---|---|---|
| x = 6，**有** break | 1 | **0** |
| x = 6，**无** break | 2 | **0** ← 拆掉 break 也是 0 |
| x = 7，有 break（从未触发） | 0 | **1** |

**第二行是铁证**：把 `break` 拿掉，`else if` 依然是 0 次 → **进不进 `else if` 跟 `break` 无关。**

**真正的规则：**

> `if / else if / else` 是一家人，**一轮只进一个**。
> `if` 一成立 → 执行 `if` 块 → **其余分支整段跳过**，
> 而且 `else if` 的条件**连算都不会算**（不是"算了但不进"）。

**为什么容易误以为是 break 的功劳：**

`break` 只可能写在 `if` 块里。而 `if` 成立的那一刻：
- `break` 会执行
- `else if` 已经注定进不去

**两件事由同一个原因（`if` 成立）引起 —— 看着像因果，其实是同一个因的两个果。**
反过来说更清楚：**`else if` 有机会被判断的时候，`break` 一定不会执行**（那时 `if` 不成立）。

**顺便校准 `break` 的作用范围：**

| 说法 | 对不对 |
|---|---|
| `break` 跳出 `if` | ✗ —— `break` 不理会 `if`，它只管循环 |
| `break` 跳出**它所在的那层**循环（或 switch） | ✓ |
| `break` 跳到 `else` | ✗ —— 跳出去之后就不再回到这个选择链了 |

写在**内层** `for` 里 → 只跳出内层 `for`，外层继续下一轮；
写在**外层** `while` 里 → 整个循环收工。

**补充（2026-10-04 他的总结："是不是就看条件，满足就进去，不满足就不进？"）**

对一半。**单看 `if`，他说的完全对。但 `else if` 多一道关卡：**

> `else if` 要进得去，必须同时满足两条：
> ① **轮到你**（前面 `if` / `else if` 全落空）② **你的条件成立**。

最硬的证据 —— **两个条件都是真的，`else if` 依然进不去**：

```c
int i = 2;
if (i == 2) {
    printf("进了 if\n");
} else if (i == 2) {            /* 条件也是真的 */
    printf("进了 else if\n");    /* 但这行永远不执行 */
}
```

gcc 实测（把 `else if` 的条件写成一个恒真的函数，函数里偷偷记数）：

```
进了 if 分支
→ else if 的条件被算了几次？ 0 次
```

**注意措辞：不是"算了但不满足"，是"根本没算"。**

| 分支 | 它判断什么 |
|---|---|
| `if` | 只看条件 |
| `else if` | **先看排队**（前面全落空了吗）→ **再看条件** |
| `else` | 从不看条件（前面全落空，就轮到我） |

**整条链一句话**：从上往下扫，**碰到第一个成立的，进去做完，整段结束**；
后面的分支**连条件都不评估**。

→ 回到素数代码：`if (x % i == 0)` 一旦成立，那个（假想的）`else if` 条件根本不会被计算。
（"没被评估"和"评估后不满足"结果一样，但机制不同 —— **条件里一旦有函数调用/自增，这个差别就会显形**。）
