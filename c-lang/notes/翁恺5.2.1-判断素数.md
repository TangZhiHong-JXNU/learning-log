# 翁恺 5.2.1 判断素数（他自己先设计了一版算法）

> 起因：2026-10-04 晚，他还没看 5.2.1，先自己想了套做法来对答案：
> "让 n 当被除数，除数从 1 试到 n，要用到浮点数，每轮除数加 1；如果结果是点几不是点 0，
> 就说明它不是素数。但我要怎么考虑走出这个循环？"

## 一、先对齐一件事：除得尽 ≠ 素数

| `n / i` 的结果 | 数学含义 | 能说明什么 |
|---|---|---|
| **除得尽**（余数为 0） | `i` 是 `n` 的因子 | **n 不是素数**（找到一个因子就够了） |
| **除不尽**（有余数） | `i` 不是因子 | **什么也没证明**，继续试下一个 i |

> 只有「**2 到 n-1 全部试完、一个因子都没找到**」这一种情况，才能说明 `n` 是素数。
> **除不尽是常态，不是结论。** 方向搞反，程序会把所有数判成非素数。

## 二、别用浮点数，用 `%`（取余）

你想到浮点，是因为整数除法会丢小数：`7 / 2 = 3`，看不出"除不尽"。
但 C 里有**专门干这件事**的运算符：

```c
if (n % i == 0) { /* 余数为 0 → 除得尽 → i 是因子 */ }
```

一行解决，纯整数运算，零误差。

### 实测对照（2026-10-04，gcc 跑过）

| n | 浮点法（转 double） | 忘转 double 的浮点法 | 取余法 | 正确答案 |
|---|---|---|---|---|
| 1 | 判为素数 ✗ | 判为素数 ✗ | 判为素数 ✗ | 不是素数 |
| 2 | 判为素数 ✓ | 判为素数 ✓ | 判为素数 ✓ | 是素数 |
| 3 | 判为素数 ✓ | **判为非素数 ✗** | 判为素数 ✓ | 是素数 |
| 4 | 非素数 ✓ | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 35 | 非素数 ✓ | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 49 | 非素数 ✓ | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 97 | 判为素数 ✓ | **判为非素数 ✗** | 判为素数 ✓ | 是素数 |

**两个结论：**

1. 你的思路**能跑通**（第 2 列全对），但要多写一次 `(double)` 转换——**一旦忘了转**，
   整数除法先发生，结果永远是"整数值"，于是 3 和 97 这些真素数被误判（第 3 列）。
   这正是你 10 月 2 日踩过的整数除法坑，换了个地方又冒出来。
2. **浮点相等比较本身不可靠**：实测 `0.1 + 0.2 == 0.3` 的结果是 **0（不成立）**。
   "看到小数点后是 0 就认为整除"这种判断法，在别的场景一定会翻车。

> **能用整数运算解决的事，别请浮点数出场。**

## 三、"怎么走出循环"——钥匙是把两件事分开

| 要下的结论 | 什么时候才能下 | 允许的出口 |
|---|---|---|
| **它不是素数** | 一发现某个 `i` 能整除，**当场就能断定** | 可以**提前跳出去**（中途退出） |
| **它是素数** | 必须把 2…n-1 全试完、一个因子都没找到 | 只能**等到最后**（自然结束） |

> 两个结论的"时机"不同 —— 这就是循环出口该怎么写的根源。

## 四、三条出口路线（第三列已由他自己答出）

| 路线 | 循环怎么写 | 循环结束后，靠什么知道结果？ |
|---|---|---|
| ① 找到因子就 `break` | `for (i = 2; i < n; i++) { if (n % i == 0) break; }` | **看 `i` 停在几**：`i == n` → 素数；否则不是 |
| ② 不 break，用标志变量 | `for (i = 2; i < n; i++) { if (n % i == 0) { 标志置 0; } }` | 结束后看标志还等不等于 1 |
| ③ 把条件写进循环头 | `i = 2; while (i < n && n % i != 0) i++;` | 同 ①：看 `i` 是否等于 n |

**关键难点（路线 ①）**：`break` 一按就跳出来了 —— 那循环结束那一行，
你怎么区分它是**提前跳出来的**，还是**全部试完自然结束的**？

> **他的答案（2026-10-04）：「看这个数有没有到 n。」—— 对。**

精确一点：**自然结束时 `i` 恰好等于 `n`**（条件是 `i < n`，`i` 要加到 `n` 才被挡下来）；
**中途 break 时 `i` 停在那个因子处，必然 `< n`**。所以 `if (i == n)` 一行就分开了两种情况。

> 这就是 **`break` 的代价**：它只告诉你"结束了"，不告诉你"为什么结束"。
> 要找回这个信息，就得**留个痕迹**（标志变量）或者**看变量停在哪儿**。

### 实测三条路线（2026-10-04，gcc 跑过）

| n | ① break + `i == n` | `i` 停在哪 | ② 标志变量 | ③ while 条件 | 真值 |
|---|---|---|---|---|---|
| 1 | 非素数 ✓ | `i=2` | **素数 ✗** | 非素数 ✓ | 非素数 |
| 2 | 素数 ✓ | `i=2` | 素数 ✓ | 素数 ✓ | 素数 |
| 3 | 素数 ✓ | `i=3` | 素数 ✓ | 素数 ✓ | 素数 |
| 4 | 非素数 ✓ | `i=2` | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 9 | 非素数 ✓ | `i=3` | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 35 | 非素数 ✓ | `i=5` | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 49 | 非素数 ✓ | `i=7` | 非素数 ✓ | 非素数 ✓ | 非素数 |
| 97 | 素数 ✓ | `i=97` | 素数 ✓ | 素数 ✓ | 素数 |
| 100 | 非素数 ✓ | `i=2` | 非素数 ✓ | 非素数 ✓ | 非素数 |

**读表**：真素数那一行，`i` 会一路走到 `n`（97 停在 97）；非素数那几行，`i` 停在**最小的那个因子**上（9→3、35→5、49→7）。

## 五、⚠️ 这条技巧的边界：它和"循环条件怎么写"是绑死的

`i == n` 之所以成立，全靠条件写的是 `i < n`。**条件一改，这招立刻失效：**

| 如果以后把条件优化成 | 自然结束时 `i` 停在 | `i == n` 还成立吗 |
|---|---|---|
| `i < n`（现在） | `i = n` | ✓ |
| `i <= n / 2` | `i = n/2 + 1` | ✗ 必废 |
| `i * i <= n`（常见优化） | `i ≈ √n + 1` | ✗ 必废 |

> 所以这是"**依赖具体写法**"的技巧：以后优化循环条件时，**必须同步改判断那一行**，
> 否则程序不报错，但答案会悄悄变错。这和 4.3.3 那节"别依赖运算符的隐式规则"是同一条原则。

## 六、两个边界（已实测）

- **`n = 2`**：`for (i = 2; i < 2; i++)` 一次都不跑 → `i` 停在 2 = `n` → 判为素数 ✓
- **`n = 1`**：数学上 1 不是素数。
  - 路线 ①③ **自动判对了**：`i` 停在 2，`2 != 1` → 非素数 ✓
  - 路线 ② **判错了**：循环一次没跑，标志没被改过，还是 1 → 判成素数 ✗
  - ⚠️ 但 ① 的"对"是**巧合**（只是 `i` 的初始位置恰好不等于 `n`），不是设计出来的。
    真要稳妥，还是开头加一句：`if (n < 2) { 直接输出"不是素数"; return 0; }`
- **`n <= 0`**：同样建议开头挡掉，别让题目以外的输入进来搅局。

# 第二部分：这堂课（5.2.1）真正教的是什么
> 2026-10-04 他看完视频后问："他用了 isPrime 来证伪和证实，还用 break 跳出循环……这堂课我能学到什么？"

## 七、翁恺的两个工具，分工完全不同

```c
int isPrime = 1;                    /* ① 先"假设"它是素数 */
for (i = 2; i < n; i++) {
    if (n % i == 0) {               /* ② 找到一个反例 */
        isPrime = 0;                /*    推翻假设 */
        break;                      /* ③ 已经够了，不用再跑 */
    }
}
if (isPrime) ...                    /* ④ 假设有没有被推翻？ */
```

| 工具 | 它负责什么 | 类比 |
|---|---|---|
| `isPrime`（flag 变量） | **结论**——"有没有被推翻过" | 记分牌 |
| `break` | **时机**——"什么时候可以收工" | 哨声 |

> **一个管"结论"，一个管"停止"——两件事分开管，代码就清楚。**
> 这和 `sign` 那节的"符号与数值分开"是**同一个思想**：一件事，一个变量/一个动作。

## 八、思维模式：默认 + 证伪（"无罪推定"）

- 判决"**是**素数"很难 —— 必须把 2…n−1 **全部**试完
- 推翻"**是**素数"很容易 —— **一个反例就够**

于是程序员的写法是三步：

1. **先假定结论成立**（`isPrime = 1`）
2. **专门去找反例**（`n % i == 0`）
3. **找不到反例，就维持原判**

法律上这叫 **"无罪推定"**：先假定无罪，由检方去找证据；找不到 → 无罪。
程序里到处都是这个模式：**默认通过，发现例外就否决**（校验、黑名单、白名单……）。

> 这和你上一轮自己答出的那条完全同一件事：
> **"不是素数"可以提前断定，"是素数"必须试完** —— break 专管前者，isPrime 收后者。

## 九、flag 变量第二次出现 —— 这是"该记住"的信号

| 课 | 变量 | 记的是什么 | 取值范围 |
|---|---|---|---|
| 4.3.3 整数反转 | `sign` | 正 / 负 | −1 / 1 |
| 5.2.1 判断素数 | `isPrime` | 是 / 不是素数 | 1 / 0 |

同一个套路**第二次出现**，就说明它不是这道题的专属技巧，而是**通用工具**。
以后凡是"整个过程只记一个状态、最后才用"的东西，都是 flag。

## 十、实测：`break` 到底省了多少（2026-10-04，gcc 跑过）

| n | 甲：不 break（试了几轮） | 乙：isPrime + break | 丙：只 break，忘改 isPrime |
|---|---|---|---|
| 6 | `isPrime=0` 试 **4** 轮 | `isPrime=0` 试 **1** 轮 | **`isPrime=1` 试 1 轮 ✗** |
| 9 | `isPrime=0` 试 **7** 轮 | `isPrime=0` 试 **2** 轮 | **`isPrime=1` 试 2 轮 ✗** |
| 100 | `isPrime=0` 试 **98** 轮 | `isPrime=0` 试 **1** 轮 | **`isPrime=1` 试 1 轮 ✗** |
| 97 | `isPrime=1` 试 95 轮 | `isPrime=1` 试 95 轮 | `isPrime=1` 试 95 轮 ✓ |

**读表三条：**

1. **合数省得多**（100：98 轮 → 1 轮），**素数一分不省**（97 两版都是 95 轮）
   → 因为素数**根本没有反例**，`break` 压根不触发。
   → **`break` 只在"已经知道答案"的时候才起作用。**
2. **丙（经典 bug）**：break 跳出来了，但结论没写下来 —— `isPrime` 还是 1，
   于是 6 / 9 / 100 全被判成素数。**程序不报错，答案全错。**
3. 正确顺序：**先写结论，再 break**（或写在同一个 `{ }` 里）。

## 十一、两个最容易写错的地方

| 错误 | 后果 |
|---|---|
| 只 `break`，忘了改 `isPrime` | 所有合数都被判成素数（见上表丙） |
| `isPrime` 初值写成 `0` | 没被推翻时也判"不是素数"，全错 |

> **初值 = "什么都没发生"时的默认答案。** 这和"阶乘初值必须是 1"是同一类问题：
> 想清楚"一轮都没跑"时该输出什么，初值就定了。

## 十二、`break` 的三条边界（以后会咬人）

1. **只跳出最里面那一层循环**：双层循环里，`break` 跳的是内层，外层照跑（以后讲）。
2. **和 `if` 里的条件绑死**：条件写错 → 该跳的不跳。
3. **它不告诉你"为什么出来"** —— 所以要么留着 `isPrime` 收结论，要么循环后看 `i` 停在哪儿。

# 第三部分：视频最后那个"替代方案"，为什么他说不好
> 2026-10-04 他问："视频最后他提出用『判断 i 最后会不会等于 n』替代 isPrime，但他觉得不好。你觉得呢？"

## 十三、实测：两种写法的正面对撞（gcc 跑过）

四版代码，同一组输入 `2 3 4 6 9 35 49 97 100`：

| n | A `i<n` + `i==n` | B `i<=n/2` + `i==n` | C `i*i<=n` + `i==n` | D `isPrime` 标志 | 真值 |
|---|---|---|---|---|---|
| 2 | 素数 | 素数 | 素数 | 素数 | 素数 |
| 3 | 素数 | **非素数 ✗** | **非素数 ✗** | 素数 | 素数 |
| 4 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |
| 6 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |
| 9 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |
| 35 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |
| 49 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |
| 97 | 素数 | **非素数 ✗** | **非素数 ✗** | 素数 | 素数 |
| 100 | 非素数 | 非素数 | 非素数 | 非素数 | 非素数 |

**A 全对，D 全对，B 和 C 只在"素数"上错。**

为什么错得这么"挑食"？看素数 97 时循环变量最后停在几：

| 循环条件 | 97 → i 最终停在 | `i == n` 成立吗 |
|---|---|---|
| `i < n` | 97 | ✓ |
| `i <= n / 2` | **49** | ✗ |
| `i * i <= n` | **10** | ✗ |

> **合数照样判对**，因为合数是被 `break` 打断的，`i` 本来就卡在因子那里、必然不等于 `n`。
> **只有素数会出错**——素数"走到头"了，但走到的头是**优化后的边界**，不再是 `n`。

**这就是"不好"的核心：错误不报、不错得明显，只在特定输入上悄悄翻车。**

## 十四、`i == n` 身上绑着三条"隐藏契约"

它能成立，靠的是下面三件事**同时**成立：

| # | 契约 | 一旦改动的后果 |
|---|---|---|
| ① | `i` 的**起点是 2** | 起点改成 3，`n=2` 就判错 |
| ② | 条件是 **`i < n`** | 改成 `i <= n/2`、`i*i <= n` → 素数全错（见上表） |
| ③ | 步进是 **`i++`** | 改成 `i += 2`（跳过偶数）→ `i == n` 永远不成立 |

**这三条契约没写在代码里，只存在于作者脑子里。** 半年后你（或别人）来优化这个循环，
只要动了其中任意一条，**编译器一个字都不会提醒你**。

## 十五、现代 C 写法里它直接编译不过（实测）

这条最硬——现在大家习惯把 `i` 声明写在 for 里：

```c
for (int i = 2; i < n; i++) if (n % i == 0) break;
if (i == n) ...        /* ✗ i 出了 for 就不存在了 */
```

gcc 实测报错：

```
error: 'i' undeclared (first use in this function)
```

> **用 `i == n` 判断，你就被迫把 `i` 声明到循环外面**——这在一个"只用来数数"的变量身上，
> 属于把它的作用域白白放大到整个函数。**这是写法上的倒退。**

## 十六、但我不同意"这技巧本身坏"——它换个场景就是标准写法

**判断标准是这一条：你要的答案，本身是不是"位置/下标"？**

| 场景 | 你要的答案 | `i` 的终值 | 用 `i == n` 合适吗 |
|---|---|---|---|
| 判断素数 | 是 / 否（一个布尔结论） | 只是**副产品** | ✗ 不合适 |
| **在数组里找一个数** | **它的下标** | **正是答案本身** | ✓ **这就是标准写法** |

查找某个数在哪：

```c
for (i = 0; i < len; i++)
    if (a[i] == target) break;
if (i == len) printf("没找到\n");   /* 走到头 = 没找到，天经地义 */
else          printf("在下标 %d\n", i);
```

这里 `i` 终值**就是**答案，边查边顺手拿到结论，一句废话没有。

> **所以不是"读循环变量"这个动作坏，而是当结论另有所属时，拿副产品顶替结论，才叫坏。**
> 判断素数要的是"是/否"，`isPrime` 是专门为此存在的变量；让 `i` 兼职，就是**用一个变量的两个职责互相耦合**。

## 十七、还有两条更细的理由

**1. 可调试性**：
- `isPrime` 版可以在循环里 `printf("i=%d isPrime=%d\n", i, isPrime);` 直接看结论什么时候被改
- `i == n` 版你只能跑完之后回头推断"它刚才是不是被 break 过"

**2. 抗演化**：哪天你出于别的理由在循环里加了第二个 `break`（比如"太大就放弃"），
`i == n` 立刻开始说谎——它分不清是哪个原因让循环停的。

**3. 没有任何性能收益**：`i == n` 和 `if (isPrime)` 都是 O(1)，一次比较。
唯一的"好处"是少声明一个变量——**而这点节省，正是靠"把一个变量用成两个用途"换来的。**

## 十八、更好的替代方案：等学了函数，flag 会升级成 return

```c
int isPrime(int n) {
    for (int i = 2; i < n; i++)
        if (n % i == 0) return 0;   /* 找到因子：直接返回"不是" */
    return 1;                        /* 全试完：返回"是" */
}
```

实测 `isPrime(6)=0`、`isPrime(97)=1`、`isPrime(2)=1` 全对。

**这就是 flag 变量的升级形态**：`isPrime` 那个变量的职责（记住结论），
被函数的**返回值**接管了——返回值天生就是"这个函数给出的结论"。

**路线优劣排序**：

| 排序 | 写法 | 结论放在哪 | 循环条件改动安全吗 |
|---|---|---|---|
| 最好 | 函数 + `return` | 返回值 | ✓ |
| 好 | `isPrime` flag + `break` | 专门的变量 | ✓ |
| 能用但脆弱 | `i == n` | 循环变量的终值 | ✗（见 §十四） |
| 错 | 只 `break` 忘改 flag | 哪都没放 | ✗ |

## 十九、这条和第 4.3.3 是同一个问题的第三次

| 课 | 一件事 | 被塞进一个变量的两件事 |
|---|---|---|
| 4.3.3 整数反转 | 符号 | 符号 vs 数值 |
| 5.1.1 阶乘 | 输入数据 | 输入的 `n` vs 计数的 `i` |
| **5.2.1 判断素数** | **结论** | **循环控制 vs 判定结果** |

> **第三次了。** 一条原则要出现三次才能叫"通用原则"——这次算数了：
> **一个变量只担一件事。想让它兼职，先问"兼职之后，改动会不会互相牵连"。**
