# 翁恺 3.2.5 if 语句再探（5 分 27 秒）

> 副标题就是它的全部内容：**if 和 else 后面也可以没有 `{}`，而只有一条语句。**

---

## 一、这节讲什么

```c
if (总分钟 < 0)
    总分钟 = 60 + 总分钟;    /* 只有这一行归 if 管 */
```

不加大括号时，**if 只拥有和控制紧跟在它后面的那一条语句**。
上面这句 `if` 和赋值语句分了两行写，但赋值语句末尾有 `;`，
而 `if (...)` 那一行末尾**没有** `;` —— 这就是它俩是一家的证据。

同理，`else` 后面也可以只跟一条语句。

---

## 二、为什么不建议这么写（实测）

拿你自己 `时间差计算.c` 那个借位逻辑做实验，两种写法跑同一组数据：

| 输入 | 有 `{}` | 没有 `{}` |
|---|---|---|
| `11 20` / `13 10`（要借位，条件成立） | `1小时50分` | `1小时50分` |
| `1 15` / `2 30`（不借位，条件不成立） | `1小时15分` ✅ | **`0小时15分`** ❌ |

没大括号的版本：

```c
if (im < 0)
    im = 60 + im;
    ih--;              /* ← 缩进跟上面对齐，看着像在 if 里，其实无条件执行 */
```

**关键：`ih--;` 无论条件成立与否都会执行**，所以小时数白白被减了 1。

→ 这就是翁恺说的：**缩进格式不能暗示 else 与 if 的匹配，缩进是骗人的。**
C 语言根本不看缩进，它只看 `{}` 和分号。

---

## 三、这节的结论（翁恺的原话精神）

> **在 if 或 else 后面总是用 `{}`，即使只有一条语句。**

理由：
- 省两个字符，换来的可能是几小时的排错
- 以后往里加第二行时，不会忘记补括号
- 对程序运行效率**完全没有影响**（只是多敲两个键）

---

## 四、顺带两个"if 常见错误"（翁恺后面会集中讲）

**① if 后面多了个分号**

```c
if (x > 100);            /* ← 这个分号把 if 结束了，后面的语句脱离控制 */
    printf("这句照样打印");
```
我实测过：即使 `x = 10`，那句 printf 也照打不误。编译器**不报错**。

**② `==` 写成 `=`**（上一节讲过）
```c
if (a = b)    /* 赋值，不是比较 → 只要 b 非 0，条件永远成立 */
```

---

## 五、下一节预告（3.3.1 嵌套的 if-else，11:37）

这节的坑会再深一层：**else 总是和离它最近的那个 if 匹配**。

```c
if (gameover == 0)
    if (count > 20)
        printf("A 赢");
else                      /* ← 你以为它属于第一个 if */
    printf("B 赢");       /*   实际它属于第二个 if */
```

解法还是同一条：**永远加大括号。**
