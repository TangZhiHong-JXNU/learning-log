## 一、这一节其实在讲什么

一句话：**把「三位数水仙花」推广到「任意 N 位」，过程中第一次出现三层循环。**

你 5.3.2 学的是「**给定一个数**，把它拆开」。  
这一节多了两样东西：

|       | 5.3.2          | 6.1.2            |
| ----- | -------------- | ---------------- |
| 要试几个数 | 就一个（读进来的）      | **一整批**（所有 N 位数） |
| 拆     | 剥位 `%10` `/10` | 一样               |
| 乘方    | 没有             | **每一位要乘 N 次**    |

所以要加两层壳：**外层选数** + **内层乘方**。中层的剥位是你已经会的。

---

## 二、题目原文

> 水仙花数是指一个 N 位正整数（N ≥ 3），它的每个位上的数字的 **N 次幂**之和等于它本身。  
> 例如：153 = 1³ + 5³ + 3³。  
> 本题要求编写程序，计算所有 N 位水仙花数。

|    |                         |
| -- | ----------------------- |
| 输入 | 一个正整数 N（3 ≤ N ≤ 7）      |
| 输出 | 按递增顺序输出所有 N 位水仙花数，每个占一行 |

**逐字读这句：「每个位上的数字的 N 次幂」。**

3 位数就立方，5 位数就 5 次方，7 位数就 7 次方 —— **不是固定的立方，是跟着位数走的方**。  
这就是为什么代码里非要再嵌一层循环来算乘方，而不能写死 `a*a*a`。

## 四、程序骨架：三层循环，一层一件事

```
① 外层  while (i < first * 10)          决定「这一轮试哪个数」
   └ ② 中层  do { d = t % 10; t /= 10; }  把这一个数拆开
        └ ③ 内层  while (j < n) { p *= d; }  把这一位乘 n 次
```

对应到你写过的东西：

| 层    | 从哪儿来                                  |
| ---- | ------------------------------------- |
| ① 外层 | **新的** —— 5.3.2 只有一个数，没有这层壳           |
| ② 中层 | **就是 5.3.2 的剥位**（`%10` `/10`），一模一样    |
| ③ 内层 | **新的** —— 位置像 5.2.2 素数表的「内层试除」，用途换成乘方 |

**本节真正新的只有两层壳（① 和 ③），中层是旧货。**

## 五、`first` 是什么 —— 不是旗子，是「最小的 N 位数」

⚠️ **注意：这个 `first` 和 5.x 整数集里的 `first` 不是一回事。**

- 5.x 里的 `first`：**「我是不是第一个」**&#x7684;旗子，取值 0/1
- 6.1.2 里的 `first`：**10^(N−1)**，也就是 N 位数里最小的那个 —— N=3 → 100，N=5 → 10000

所以外层范围 `[first, first*10)` 正好圈住「所有 N 位数」，一个不多一个不少。

### 它和你 5.3.2 算的 `mask` 是同一个数

|      | 5.3.2 · mask           | 6.1.2 · first       |
| ---- | ---------------------- | ------------------- |
| 手里已知 | 一个具体的**数** x           | 只知道**位数** n         |
| 循环条件 | `while (t > 9)`        | `while (i < n)`     |
| 循环体  | `t /= 10; mask *= 10;` | `first *= 10; i++;` |
| 结果   | 10^(x位数−1)             | 10^(n−1)            |

**同一件事：一个从「数」反推位数，一个从「位数」直接算。**

### 本机实测：两种起步值

| n | `i = 1; while (i < n)` | `i = 0; while (i < n)` |
| - | ---------------------- | ---------------------- |
| 3 | 100                    | 1000 ← 偏大 10 倍         |
| 4 | 1000                   | 10000                  |
| 5 | 10000                  | 100000                 |
| 6 | 100000                 | 1000000                |
| 7 | 1000000                | 10000000               |

⚠️ **这就是你 5.3.2 踩过的那个「偏大 10 倍」，换身衣服又回来了 —— 同一个坑。**  
判别口诀不变：**数「乘了几次 10」，不是数「循环跑了几轮」。**  
`i = 1` 起步才走 n−1 轮；`i = 0` 起步走 n 轮，多乘一个 10。

### 那为什么不能「先数出位数」，再往下跑？

**因为程序一开始，手里一个数都没有。**「数位数」需要拿一个数当输入，
可那些数（100、101…999）是**后面才被造出来的**；要造它们，又得先知道是几位。
**第一个箭头就断了。**

就算硬抓一个数去数（本机实测）：

```
x = 153     ->  mask = 100      (它是 3 位数)
x = 12345   ->  mask = 10000    (它是 5 位数)
x = 7       ->  mask = 1        (它是 1 位数)
```

**你抓哪个数，就得到哪个位数** —— 那是「那个数」的属性，不是「题目」的要求。
抓 12345 数出 5，难道去求"所有 5 位水仙花数"？题目要的是三位数。

| | 5.3.2 | 6.1.2 |
| --- | --- | --- |
| 位数从哪来 | 从题目给的数身上**发现** | 题目直接**指定**（输入 N） |
| 要不要数位数 | **要** | **不要** |
| 手里先有什么 | 一个数 | 一个位数 |

⚠️ **但「先数出位数」在另一道题里完全正确**：如果题目是
「**输入一个数，判断它是不是水仙花数**」，那 N 就是"这个数自己的位数"，**必须数出来**：

```c
int x;  scanf("%d", &x);
int t = x, digits = 0;
while (t > 0) { t /= 10; digits++; }   /* ← 这道题里必须有，不能省 */
/* 之后拿 digits 当 N 往下跑 */
```

**同一个知识点，两种题目，一正一反。**
翁恺这一节是后者（输入 N 找一批数），所以通篇不需要数位数。

## 六、为什么这题**用不上 mask**

拿 153 走一遍中层（本机实测）：

```
d = 3   d³ = 27    sum = 27    t 剩 15
d = 5   d³ = 125   sum = 152   t 剩 1
d = 1   d³ = 1     sum = 153   t 剩 0
最终 sum = 153   ==   153   ✓
```

剥出来是 **3 → 5 → 1**，**倒着的**。但题目只要「三位立方和」，**求和跟顺序无关**。

所以：**5.3.2 的正序分解非用 mask 不可，是因为它必须按顺序把数字打出来；  
这里不输出数字、只求和，mask 就省了。**

> 视频里你也见不到 `mask` —— 见到的是 `t = i` 这个副本。

## 七、`t = i` 这个副本在干什么

外层拿 `i` 当「要试的数」，中层要拿它去剥位 —— 而**剥位会把数改没**（`t /= 10` 一路砍到 0）。

直接剥 `i` 的话，外层就没得遍历了。所以：

```c
int t = i;    /* 剥副本，i 一点不动 */
```

**这是「动手前先留副本」，第三次出现了**（5.3.2 的 `t`、整数集的那次、这次）。

### 本机实测：不留副本，直接在循环里改循环变量

```c
for (n = 100; n <= 999; n++) {
    ...
    n /= 10;      /* 灾难 */
}
```

真实输出：

```
rounds = 20000 , found = 19997      ← 20000 轮是我手动刹车，它根本停不下来
```

**为什么停不下来**：`n` 被一路砍小，砍到 `n = 1` 时 —— `1 / 10 = 0`，然后 `n++` 又把它变回 `1`，  
`1 / 10 = 0`，`n++` 又回 `1` …… **永远卡在 1 出不去**。

（顺带一个好习惯：跑任何「可能停不下来」的程序，先在心里给它留个刹车 ——  
这次是我在循环条件里塞了 `guard < 20000`，否则就要 Ctrl+C 了。）

## 八、本机实测：五个必踩的坑

| # | 写法                             | 真实结果               | 病根                    |
| - | ------------------------------ | ------------------ | --------------------- |
| 1 | `a*3 + b*3 + c*3` 当立方和         | 全表找到 **0 个**       | `*3` 是「乘 3」，不是三次方     |
| 2 | `int p = 0;` 之后 `p *= d;`      | sum 恒为 **0**       | 0 乘任何数都是 0，累加器起步必须是 1 |
| 3 | `i = 0; while (i < n)` 算 first | **偏大 10 倍**        | 多走一轮                  |
| 4 | 循环体里改 `i` / `n`                | **死循环**（20000 轮未停） | 循环变量被吃掉了              |
| 5 | 中层用 `while` 而不是 `do-while`     | 本题**结果一样**         | 见下                    |

坑 1 的证据（`153` 两套公式对照）：

```
a*a*a + b*b*b + c*c*c  =  1 + 125 + 27  =  153   ✓
a*3   + b*3   + c*3    =  3 +  15 +  9  =   27   ✗
```

坑 5 的证据（剥位顺序）：

```
do-while 剥出来：3 5 1
while    剥出来：3 5 1        ← 完全一样
```

**为什么本题两者一样**：外层遍历的 `i` 最小也是 `first ≥ 100`，所以副本 `t` 永远 > 0，  
`do-while` 那句"至少执行一次"的优势用不上 —— 这跟 5.3.2 里「输入 0 才必须用 do-while」正好互补。

## 九、性能：为什么 N 只到 7

本机统计（外层跑多少轮、总共做多少次乘法）：

| N | 外层次数      | 乘法次数        | 实测耗时       |
| - | --------- | ----------- | ---------- |
| 3 | 900       | 8,100       | 瞬间         |
| 4 | 9,000     | 144,000     | 瞬间         |
| 5 | 90,000    | 2,250,000   | 瞬间         |
| 6 | 900,000   | 32,400,000  | 0.1 秒级     |
| 7 | 9,000,000 | 441,000,000 | **1.28 秒** |

乘法次数 = 外层次数 × 位数 × N = 9×10^(N−1) × N²。

**N 每加 1，工作量涨 10 倍出头。** N=7 已经是 4.4 亿次乘法、1.28 秒；  
再往上就是「能算但没必要」了。

**为什么题目卡在 N ≤ 7**：因为 **8 位水仙花数一个都没有** —— 不是算不出来，是不存在。  
（9 位又有，但 10 位的最大数 4679307774 已经超过 int 的 21 亿 —— 那时才轮到 6.1.1 讲的  
`long long` 上场。）

## 十二、翁恺原版 · 逐行拆解（看完视频回来补的）

> 起因：看完视频说「后面的没看懂」。这一节把整段代码切成 4 块，
> 每块配一段**本机实测的执行过程**（把每轮的值全打出来）。

### 12.1 整段代码，先标块

````c
int n;
scanf("%d", &n);

/* ─────────── A 块：算出「最小的 N 位数」 ─────────── */
int first = 1;
int i = 1;
while (i < n) {          /* 这里的 i 只是个计数器 */
    first *= 10;
    i++;
}

/* ─────────── B 块：一个一个试 ─────────── */
i = first;               /* ← i 在这里变身 */
while (i < first * 10) {

    /* ─────────── C 块：把这个数拆开 ─────────── */
    int t = i;           /* 副本：i 不能动，让 t 去被剥 */
    int sum = 0;         /* 每换一个 i 都要从 0 重新攒 */
    do {
        int d = t % 10;  /* 剥出末位 */
        t /= 10;         /* 末位扔掉 */

        /* ─────────── D 块：算这一位的 n 次方 ─────────── */
        int p = 1;
        int j = 0;
        while (j < n) {
            p *= d;
            j++;
        }

        sum += p;        /* 攒进总和 */
    } while (t > 0);

    /* ─────────── 判断 ─────────── */
    if (sum == i) {
        printf("%d\n", i);
    }
    i++;                 /* 走到下一个数 */
}
````

**先记住这 4 块的位置，再看下面。整段代码其实只有 4 件事。**

### 12.2 ⭐ `i` 这个变量被用了两次（最迷惑的地方）

| | A 块里的 `i` | B 块里的 `i` |
| --- | --- | --- |
| 值 | 1 → 2 → 3 | 100 → 101 → … → 999 |
| 角色 | **计数器**（数 first 乘了几次 10） | **被试的那个数** |
| 怎么进去的 | `int i = 1;` | `i = first;` ← 重新赋值 |
| 用完怎样 | 停在 3，**没用了** | 每轮末尾 `i++`，一直往前走 |

**A 块留下的 `i = 3` 和 B 块的 `i` 毫无关系** —— 同一张名字，换了个岗位。
（和 5.3.2 里「两个 `t` 同名不同命」是同一类坑，这是第二次了。）

### 12.3 A 块实测（n=3，真跑输出）

```
判断 i=1 < n=3 ? 是  ->  first: 1 变 10 ，i 加 1 变 2
判断 i=2 < n=3 ? 是  ->  first: 10 变 100 ，i 加 1 变 3
判断 i=3 < n=3 ? 否  ->  停。first = 100
```

**循环体跑了 2 轮**（不是 3 轮）：`i` 是 1 和 2 的时候各跑一次，轮到 3 就进不去了。
所以 `first = 10²= 100` = 最小的三位数。**这就是 §五 那张「偏大 10 倍」表的来源。**

### 12.4 C 块 + D 块实测：153 的完整过程（真跑输出，一字未改）

```
---------- 当前 i = 153 ----------
  [中层] 剥出 d = 3      t 剩 15
       [内层] 第 1 次乘：p = 3
       [内层] 第 2 次乘：p = 9
       [内层] 第 3 次乘：p = 27
       sum 累加成 27
  [中层] 剥出 d = 5      t 剩 1
       [内层] 第 1 次乘：p = 5
       [内层] 第 2 次乘：p = 25
       [内层] 第 3 次乘：p = 125
       sum 累加成 152
  [中层] 剥出 d = 1      t 剩 0
       [内层] 第 1 次乘：p = 1
       [内层] 第 2 次乘：p = 1
       [内层] 第 3 次乘：p = 1
       sum 累加成 153
  sum = 153  ==  i = 153   ==> 打印 153
```

**照着这张表读代码，一层一层对：**

| 你在代码里看到 | 上面输出里的哪一行 |
| --- | --- |
| `int d = t % 10;` `t /= 10;` | `[中层] 剥出 d = 3   t 剩 15` |
| `while (j < n) { p *= d; }` | `[内层] 第 1/2/3 次乘：p = 3 / 9 / 27` |
| `sum += p;` | `sum 累加成 27` |
| `} while (t > 0);` | 三行 `[中层]` 走完，`t 剩 0` → 退出 |
| `if (sum == i) printf(...)` | `sum = 153 == i = 153 ==> 打印 153` |

### 12.5 三个「位置」问题（写的时候最容易摆错）

| 该写在哪 | 代码 | 为什么 |
| --- | --- | --- |
| **在中层里面、do 之前** | `int t = i;` | 每换一个 `i`，副本都要重新拿一次 |
| **在中层里面、do 之前** | `int sum = 0;` | 每换一个 `i`，总和必须清零（否则会把上一个数的和带过来） |
| **在中层里、每次剥位之后** | `int p = 1;` | **每剥一位都要从 1 重新开始乘**（不能沿用上一位的 p） |
| **在中层外面、外层里面** | `i++;` | 走下一个数。写在中层里就乱套了 |

⚠️ **`p = 1` 那个 `1` 不能写成 `0`**：`0` 乘任何数都是 `0`。
本机实测：写成 `p = 0` 之后，153 算出来 `sum = 0`，一个水仙花数都找不到。

### 12.6 一个反例：100 走一遍（真跑输出）

```
---------- 当前 i = 100 ----------
  [中层] 剥出 d = 0      t 剩 10
       [内层] 第 1 次乘：p = 0
       [内层] 第 2 次乘：p = 0
       [内层] 第 3 次乘：p = 0
       sum 累加成 0
  [中层] 剥出 d = 0      t 剩 1
       ...
       sum 累加成 0
  [中层] 剥出 d = 1      t 剩 0
       [内层] 第 1 次乘：p = 1
       [内层] 第 2 次乘：p = 1
       [内层] 第 3 次乘：p = 1
       sum 累加成 1
  sum = 1  !=  i = 100   ==> 跳过
```

**100 不是水仙花数**（`1³+0³+0³ = 1 ≠ 100`），程序算出 1，正确地跳过了。
注意 `d = 0` 那一轮：`p` 从 1 一路乘成 `0` —— **这是对的**（`0³ = 0`），
和 12.5 里那个「`p` 从 0 起步」的错法不是一回事。

### 12.7 三层各跑几次（n=3）

| 层 | 跑几次 | 干什么 |
| --- | --- | --- |
| B 外层 | 900（100~999） | 换一个数 |
| C 中层 | 每个数 3 次 | 剥一位 |
| D 内层 | 每位 3 次 | 乘一次 |

乘法总次数 = 900 × 3 × 3 = **8100 次**（和 §九 那张表对得上）。
