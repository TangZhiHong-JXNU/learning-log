# C 语言里的"符号"怎么用 —— 一元负号 & sign 变量

> 场景来源：翁恺 4.3.3 整数反转，处理负数输入。
> 2026-10-04 他问"符号的反转符号我不是很会用"，本篇专门讲透。

---

## 一、`-` 的两个身份（必须先分清）

同一个 `-`，在 C 里是**两个不同的运算符**，靠"旁边有几个操作数"来区分：

| 写法 | 名字 | 操作数个数 | 作用 | 例子 |
|---|---|---|---|---|
| `a - b` | 减号 | 2 个 | 相减 | `7 - 3` → 4 |
| `-a` | 一元取负号 | 1 个 | 求相反数 | `-(-5)` → 5 |

**一元取负 = 你说的"符号反转"**，规则：

```
 5  → -5
-5  →  5     （负负得正）
 0  →  0     （-0 还是 0）
```

### 坑：`=-` 与 `-=` 完全不同

| 写法 | 意思 | n=10 时结果 |
|---|---|---|
| `n = -n;` | 取相反数 | -10 |
| `n -= 5;` | 减 5 | 5 |
| `n = -5;` | 赋值为 -5 | -5 |

`n = -n;` 里的 `-` 是**一元的**，只是刚好挨着 `=`，别读成"等于负"。

## 二、sign 三步走：把符号"摘下来 → 干活 → 装回去"

### 完整代码

```c
int n, rev = 0, digit, sign = 1;   // sign 默认 1 = 按正数处理

scanf("%d", &n);

if (n < 0) {          // 只在它是负数时做
    sign = -1;        // ① 把"负号"摘下来存进 sign
    n = -n;           // ② 把 n 转成正数
}

while (n != 0) {      // 反转循环：这时 n 一定是正的，专心干活
    digit = n % 10;
    rev = rev * 10 + digit;
    n = n / 10;
}

printf("%d\n", sign * rev);   // ③ 把符号乘回去
```

### 实测输出（gcc 跑过）

输入 `-1234`：
```
【转正后】n=1234  sign=-1
【反转后】rev=4321
【最终输出】-4321
```

输入 `1234`：
```
【转正后】n=1234  sign=1
【反转后】rev=4321
【最终输出】4321
```

### 为什么 sign 初始值是 1

- 输入的绝大多数数是正数 → 默认 `1`，什么都不用改
- 只有真遇到负数才拨到 `-1`
- 这叫 **"默认值 + 例外处理"**，比"先算什么再修正"更清晰

## 三、符号开关的本质

`sign` 就是**一个只存 ±1 的开关**：

```
sign * 正数 = 正数
sign * 负数 = 负数
```

用 1 和 -1 相乘，就等价于"要不要加负号"。

**这个套路以后的用途**（全都长一个样）：
- 模拟银行进出账（-1 表示支出）
- 判断坐标在第几象限（x 和 y 各有符号）
- 温度转换（华氏/摄氏的温差方向）
- 向量方向的反转

## 四、常写错的 4 种

| 错误 | 现象 |
|---|---|
| `sign -1;` | 漏等号 → 编译错误 |
| `sign = 1;` 写在 `if` 里 | 负数也被强行变正，符号全丢 |
| `n = -n` 写在 `if` 外面 | 正数被转成负数，全错 |
| `printf("%d", rev)` 忘乘 `sign` | 负数输出成正数 |

## 四之二、高频疑问："输入 1234 没进 if，乘 sign 不会把它变负吗？"

**不会。** 三个要点：

1. **`sign` 的初始值是 `1`，不是 `-1`。**
   `int sign = 1;` 决定了"默认按正数处理"。没进 `if` → `sign` 原封不动还是 1。
2. **乘法只有乘 `-1` 时才翻转符号。**
   `1 × 4321 = 4321`（乘 1 等于没乘）；`-1 × 4321 = -4321`。
3. **`sign * rev` 不会改变 `rev` 本身。**
   它只是**算出一个新值**交给 `printf` 打印。`rev` 仍然是 4321。

实测（gcc）：

```
===== 输入 1234 =====
刚读完 n 时:  n=1234   sign=1
没进 if 分支:  n=1234   sign=1  (sign 原封不动)
rev=4321
sign * rev = 1 * 4321 = 4321

===== 输入 -1234 =====
刚读完 n 时:  n=-1234   sign=1
进了 if 分支:  n=1234   sign=-1
rev=4321
sign * rev = -1 * 4321 = -4321
```

**一句话**：`sign` 是"要不要加负号"的开关，**出厂默认停在"不加"（1）那一档**，
只有遇到负数才被拨到"加"（-1）那一档。

## 五、两种写法对比（选哪个）

| | 靠 `%` 自动带负号 | 用 `sign` 三步走 |
|---|---|---|
| 代码量 | 少 | 多 3 行 |
| 可靠性 | 依赖 **C99 才规定的"向 0 截断"**，老编译器可能出错 | 任何标准、任何编译器都对 |
| 可读性 | 别人看不出你考虑过负数 | 意图写在脸上 |
| 建议 | 考试赶时间可用 | **练习阶段推荐** |

**判据**：代码里靠"运算符隐式规则恰好成立"的逻辑 = 出错高发区。
显式把符号摘下来处理，才是稳的写法。

## 六、一个必须知道的边界：INT_MIN

如果输入是 `-2147483648`（int 能表示的最小值），`n = -n;` 会**溢出** ——
因为 `+2147483648` 超出 int 的最大值 `2147483647`。

现阶段知道有这回事就行，PAT 题不会这么坏。以后写健壮代码时：
```
if (n == INT_MIN) { ... 特殊处理 ... }   // 需要 #include <limits.h>
```

## 八、这种写法叫什么？能学到什么？（2026-10-04 他主动问"套路"）

### 8.1 名称（没有唯一官方名，按层面记）

| 层面 | 叫法 | 含义 |
|---|---|---|
| 变量 | **flag 变量 / 标志变量** | `sign` 只存 ±1，专门"标记状态"的小变量 |
| 结构 | **前处理 → 主处理 → 后处理** | 归一化 → 干正事 → 还原 |
| 思想 | **归一化（normalization）** | 把多种情况先整理成同一种再处理 |
| 数学 | **符号-数值分离** | 符号和绝对值当两样东西分开管 |

**`sign` 本身最标准的叫法是"标志变量（flag variable）"。**

### 8.2 可迁移的四点

1. **减少分支 = 减少 bug**
   笨办法：循环里到处 `if (n<0)`；聪明办法：进循环前统一转正，循环里只剩一种情况。
   → **"代码里能少一个分支，就少一处出错的可能。"**

2. **"准备 → 干活 → 收尾"是所有程序的基本骨架**
   前处理（读数据/归一化）→ 主处理（核心逻辑）→ 后处理（输出/还原）。
   以后写大程序先分这三块，思路不会乱。

3. **数学模型 ⇄ 计算机实现 的差别（重要）**
   数学上 `-1234` = 符号"负" + 数值 1234，和 `sign + n` 的模型一致；
   但 **C 的 int 在内存里用的是"补码"，不是"符号位+数值"**。
   补码决定了 `-1234 % 10 = -4` 这个行为。
   → **"你在用代码实现概念模型，底层硬件用的是另一套方案。"**
   这个认知对以后学计算机组成原理、做嵌入式极重要。

4. **区分"能跑"和"可靠"**
   两种写法都输出 `-4321`，区别在是否**依赖巧合**。
   判断力比记语法值钱。

### 8.3 边界：这招不是万能的

两个前提，不满足就不能用：

1. **转正过程不能溢出** —— `INT_MIN` 取负会溢出（见 §六）。
2. **"值"和"符号"真的能分开** —— 整数可以；
   但浮点的 `-0.0`、NaN 不好办；角度/坐标旋转这类符号与数据耦合的场景，硬拆反而添乱。

**判断标准**：剥离出来的信息能否"独立持有、最后无副作用地还回去"。
能，就可以用这套；不能，就别硬套。
