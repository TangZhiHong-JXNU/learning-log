## 二、头号问题：`printf("\n")` 的位置（6 次，跨题型重复）

### 两个方向都错

**方向 A：换行写进了循环体**（`sushugeshu.c`）

```c
for(i=2;i<=100;i++){
    ...
    if (isprime==1){
        printf("%d",i);
    }
    printf("\n");        /* 错：每检查一个数就换一次行 */
}
```
输出被切成 100 行，每行最多一个素数。

**方向 B：该有的地方没有**（`yuefenzuijianshi.c` 第 20 行）

```c
printf("%d/%d",x/h,y/h);    /* 缺 \n */
```

### 根因

判断 `\n` 放哪里靠的是"感觉这行该结束了"，不是确定的位置 → **同类题有时候放对、有时候放错**。

### ★ 一劳永逸的判据

> **`printf("\n")` 永远跟「一组数据输出完」绑定，不是跟「循环转了一圈」绑定。**
>
> 自检问题：**这个 `\n` 是「每轮都要」，还是「每整套只要一次」？**
> - 每行输出一个素数 → 每轮都要 → **放进"确认是素数"的 `if` 里面**
> - 输出一整串再收尾 → 只要一次 → **放最外层循环后面**

## 三、第二个问题：`for` 前面那行多余初始化（3 次）

```c
i=a;
for (i=a;i<=a+3;i++){     /* 外面这行是废的 */
```

**为什么会出现**：想"循环开始前要给它一个初值"——想法对，**只是 `for` 的第一段就是干这个的**。

> **`for (① ; ② ; ③)` = 开工前 / 每轮前检查 / 每轮收尾。①号位只执行一次，且在执行循环前。**
> **所以 `for` 的初值永远写在第一段里，不要在它前面再写一行。**

代价：不报错、不影响结果 → **"面板看不见的错误"典型**。

## 四、第三个问题：`%` 和 `/` 的类型陷阱（2 次，样题直接考）

```c
int foot=cm/30.48;                 /* double 赋给 int → 截断 */
int inch=((cm/30.48)-foot)*12;     /* 全靠 double 撑着 */
```

`feibonaqie.c` 里 `double i=2,j=1;` **是运气**：写成 `int i,j` 则 `i/j` 变整数除法，**gcc 一声不吭**。

### 样题原型

```c
int a=1, b=6, c=2, d=5;
float e = (a+b)/c + (float)(d/c);
printf("%f\n", e);
```
`(a+b)/c` = 7/2 = **3**（整数除法）；`(float)(d/c)` = 2/5 = **0**（先算再转）→ `e = 3.000000`

### ★ 口诀升级版

> **整数相除，先把结果砍成整数，才轮到赋值给谁。`(float)` 写在外面救不了里面的除法。**

## 五、第四个问题：`= / ==` —— 实测数据

### gcc 会主动警告（本机实测）

```
test.c:8:9: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
         if (i = 3)
         ^
```
> 只是 **warning 不是 error** → 照样生成 `.exe`，跑起来才死循环。**这就是它坑人的地方：不拦住你，只小声提醒。**

### 两种写法对照（本机实跑）

| | `if (i = 3)` | `if (i == 3)` |
| --- | --- | --- |
| 每轮判定 | **恒真** | 只有 i==3 那轮真 |
| 循环结束后 `i` | **3**（被打回去了） | 6（正常递增） |
| gcc 警告 | 有 | 无 |

**关键**：赋值版每轮 `i++` 之后又被 `i = 3` 打回 3 → `i` 卡住 → **永远到不了终点**。

### 记忆锚点

```c
(a = 5) 的值是 5      /* 赋值表达式的值 = 右边那个数 */
(a = 0) 的值是 0      /* 0 就是假 */
```
> **`=` 是"装进去，然后举手报出装的那个数"；`==` 是"只回答是/否，不动手"。**

### ★ 消掉"慢"的一条规则

> **看到 `if` / `while` 括号里出现单个 `=`（不是 `>=` `<=` `!=` `==`），先停一下问："我是想改它，还是想比它？"**
> 然后看 gcc 有没有报 `-Wparentheses` —— **这是少数 gcc 会主动帮你抓的错误。**

⚠️ **实测踩坑记录**：验证 `if (i = 3)` 时**两次忘记限输出**，程序各刷出 34 亿 / 19 亿字节才被系统掐断。
**以后凡是"可能跑飞"的程序：在源码里加计数器手动刹车**（如 `if (n >= 5) break;`），别只靠管道 `| head`。

## 六、★ 最重要的一张表：哪些错误 gcc 会拦

| 你的错误 | gcc 会拦吗 | 危险度 |
| --- | --- | --- |
| `if (i = 3)` | ✅ 会（`-Wparentheses`） | 中（能自己发现） |
| 缺 `&`、拼写错、缺分号 | ✅ 会（error） | 低（编译不过，跑不起来） |
| **`\n` 位置错** | ❌ **不吭声** | **高** |
| **`for` 前多余初始化** | ❌ 不吭声 | 低（结果还对，只是多余） |
| **`int` 接除法截断** | ❌ 不吭声 | **高** |

**结论**：
1. 前三类是"面板看得见"的，**只要养成看编译输出的习惯就能自己抓**。
2. **"看不见的"三类才是真正吃掉分数的** —— 这与已学过的"越安静的越坑人"是同一条线。
3. **考前一天，把这张表扫一遍。**

## 九之二、九九乘法表专项：同一道题改三轮，7 个坑（2026-10-06 21:13~23:14）

> 来源：任务栏「预习翁恺6.1.2水仙花数」，`notes/九九乘法表-改进清单.md`。
> **这是他单题踩坑最多的一次** —— 7 个坑里，有 4 个全新型，之前没统计到。
> ✅ **当前状态：他已把 `j=i` 改成 `j=1`，`pat/jiujiuchengfabiao.c` 跑出完整方阵。**

| # | 当时写的 | 现象 | 病因 | 型 |
| --- | --- | --- | --- | --- |
| 1 | `printf("i*j=%d,i*j=")` | 印出垃圾数 `11779408` | **`%d` 没给参数**；`i*j` 写成了字面文本 | 🆕 格式符与参数不配对 |
| 2 | `while(i<=j, j<10)` | 前半截白写 | **逗号表达式只取最后一个值** | 🆕 用 `,` 当 `&&` |
| 3 | `if (j = 9)` | 每轮都换行（打成对角形） | `=` 是赋值，非零恒真 | ② 重复（第 2 次） |
| 4 | `if (j == 9)` | 每行只有 8 个 | **判断早了**：`j++` 之后 `j` 是"下一个要打的" | 🆕 混淆"打之前/打之后"的 `j` |
| 5 | 缺 `printf("\n")` | 45 个算式挤成一行（`wc -l` = 0） | 换行语句整个漏写 | ① 重复（第 7 次） |
| 6 | `printf("%d*%d=%d", ...)` | `1*1=11*2=2` 粘成一坨 | 算式之间没有分隔（该用 `%-4d`） | 🆕 输出粘连 |
| 7 | `j = i` | 每行缺左边（右上三角） | 应该是 `j = 1` | 🆕 重置值取错 |

### ★ 从这 7 个坑提炼的两条新判据

**判据一：`%d` 是占位符，跟参数一对一**
> 引号里有**几个** `%d`，逗号后面就**必须有几个**参数，按顺序对上。
> 要**原样打出来的字**（`*`、`=`、`\n`）直接写在引号里，**不占参数**。
> → 坑 1、坑 6 是同一件事的两面：**占位符和参数是"一对一"关系，多一个少一个都出事。**

**判据二：四个"看起来像连接"的符号，身份完全不同**

| 符号 | 正式身份 | 能不能连接条件 |
| --- | --- | --- |
| `&&` `\|\|` | 逻辑运算符 | ✅ 这才是它的本职工作 |
| `;` | 语句结束符 | ❌ 语法错误 |
| `,` | 逗号表达式（做几件事，只取最后的值） | ❌ 前半截被扔掉 |

> **口诀：括号里要「问句」，不要「句号」也不要「然后」。**
> ⚠️ **和之前的"`for` 前多余初始化"是同一族**：`for(i=1, j=1; ...)` 里的逗号是**合法且常用**的，
> 但 `while(i<=j, j<10)` 里的逗号就是灾难 —— **同一个符号，位置不同，命运不同。**

### ★★ 判据三：`j++` 之前和之后，`j` 的含义不一样（新框架，讲循环边界必用）

| | `j` 代表什么 |
| --- | --- |
| `j++` **之前** | 正在打的**这一个** |
| `j++` **之后** | **下一个**要打的 |

> 所以判断"该不该换行"时，**先想清楚你问的是哪个时刻的 `j`** ——
> `j == 9` 是"下一个轮到第 9 个"（第 9 个还没打），`j == 10` 才是"9 个都打完了"。
> → **这是他"差一错误（off-by-one）"的第一次明确记录**，和 `while(t>9)` vs `while(t>0)` 是同一族
> （都是"数错了一轮"），但这次的抓手是**"时间点"**而不是"次数"。

### 配套关系表（换行之后 `j` 回哪）

| 想要的形状 | `if` 条件 | 换行后 |
| --- | --- | --- |
| 方阵（每行 9 个） | `j == 10` | `j = 1` |
| 三角形（第 i 行 i 个） | `j > i` | `j = 1` |

> ⚠️ **不管做方阵还是三角形，换行之后 `j` 都回到 1。** 只有 `if` 条件要改。

### 一层版 vs 两层版（为什么大家不用手工重置）

| | 一层版 | 两层版 |
| --- | --- | --- |
| 换行 | 靠 `if` 手工判断 + 手工重置 | 内层跑完自动换行 |
| 改形状 | 改 `if` 里的条件 | 改内层循环条件（`j <= 9` / `j <= i`） |
| 条件推导 | **要自己算**（"什么时候该换行？"） | **照抄题目**（"第 i 行有 i 个"） |

> ⭐ **这张表解释了他为什么会连续踩 3、4、5 三个坑** ——
> 一层版把"换行时机"变成了**必须自己推的数学题**；两层版把它变成了**照着题目抄**。
> **结论：能用两层就用两层。**

## 九之三、水仙花数（6.1.2）预习中暴露的坑（5 条，全部实测）

> 来源：`notes/翁恺6.1.2-水仙花数-预习.md` §八。**这是"还没写代码、先纸上推演"阶段抓到的。**

| # | 写法 | 真实结果 | 病根 | 与他旧坑的关系 |
| --- | --- | --- | --- | --- |
| 1 | `a*3 + b*3 + c*3` 当立方和 | 全表找到 **0 个** | `*3` 是「乘 3」，不是三次方 | 🆕 把"乘方"当成"乘以" |
| 2 | `int p = 0;` 之后 `p *= d;` | sum 恒为 **0** | **0 乘任何数都是 0**，累乘器起步必须是 1 | 🆕 乘法单位元（对照：加法用 0，乘法用 1） |
| 3 | `i = 0; while (i < n)` 算 first | **偏大 10 倍** | 多走一轮 | ② 重复（第 4 次！） |
| 4 | 循环体里改 `i` / `n` | **死循环**（20000 轮未停） | 循环变量被吃掉了 | 🆕 改循环变量 |
| 5 | 中层用 `while` 而不是 `do-while` | 本题**结果一样** | 外层最小是 100，副本永远 > 0 | — 这条是"对的" |

### ⭐ 坑 2 的判据（新，讲累加/累乘必用）

> **加法的起点是 0；乘法的起点是 1。**
> - `sum = 0` → `sum += x` 正确
> - `p = 1` → `p *= d` 正确
> - **`p = 0` → 永远 0**（被吸收了）
> 判别口诀：**"这个运算是靠谁当'单位元'活着的？"**

### ⭐⭐ 坑 3 的升级：这是「偏大 10 倍」第 4 次出现

| 时间 | 题目 | 错法 |
| --- | --- | --- |
| 10/05 | 5.3.2 整数分解 | `while(t>0)` 建 mask |
| 10/06 | 6.1.2 first（本次） | `i=0; while(i<n)` |
| 10/06 | 5.x 整数集 | 同族 |
| 10/07 | patfu.c | 第 13 行 `while(t>0)` |

> **判别口诀（已定型）：数「乘了几次 10」，不是数「循环跑了几轮」。**
> - `t > 9` / `i = 1 起步` → 走 n−1 轮 → **对**
> - `t > 0` / `i = 0 起步` → 走 n 轮 → **多乘一个 10**

### ⭐ 坑 4 的判据（新）

> **循环变量是"控制开关"，不是"工作材料"。**
> 要拿它去算，**先留副本**（`int t = i;`），副本随便改，开关不能动。
> → 这是「留副本」第 3 次出现（5.3.2 的 `t`、整数集的 `first`、这次），
> 但**这次的后果最严重**（死循环），可作最强例证。
