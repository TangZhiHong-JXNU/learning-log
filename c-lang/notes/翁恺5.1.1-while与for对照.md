# 翁恺 5.1.1 对照：while 版 ↔ for 版（阶乘）

左边是你自己一步步推出来、亲手写的；右边是视频里的标准写法。**两者逻辑一模一样，只是写法不同。**

## 一、两份代码并排看

**你写的（while 版）**

```c
int result = 1;
int i = 1;                    /* ① 初始化：孤零零待在循环上面 */

while (i <= n) {              /* ② 条件：只在这儿出现 */
    result = result * i;
    i = i + 1;                /* ③ 步进：躲在循环体最后一行 */
}

printf("%d\n", result);
```

**视频里的（for 版）**

```c
int result = 1;

for (i = 1; i <= n; i = i + 1) {   /* ①②③ 全挤在头部一行 */
    result = result * i;
}

printf("%d\n", result);
```

## 二、三件部件的位置对照（这张表是本节重点）

| 部件 | 作用 | while 版的位置 | for 版的位置 |
|---|---|---|---|
| ① 初始化 | 循环开始前，只做一次 | 循环**上面**，单独一行 | 括号里第 1 格 |
| ② 条件 | 每轮开始前，判断一次 | `while (...)` 的括号里 | 括号里第 2 格 |
| ③ 步进 | 每轮结束时，做一次 | 循环体**最后一行** | 括号里第 3 格 |

> **一句话：for 不是新语法，它只是把 while 散在三处的零件，按固定顺序收进一行。**

## 三、for 括号里三个格子的正式名字

写法：`for ( 初始化 ; 条件 ; 步进 )`

- 第 1 格 **初始化表达式** —— 进循环之前，只算一次
- 第 2 格 **条件表达式** —— 每轮开始前算一次，为真才进循环体
- 第 3 格 **步进表达式** —— 每轮循环体**结束之后**算一次

⚠️ **两个分号是硬性分隔符，永远不能省**（哪怕某一格空着）。第一次写 for 最常丢它，报错通常是 `expected ';' before ')'`。

## 四、执行顺序（不是从左到右一句句走）

写的是 `for (①; ②; ③)`，真正跑的顺序是：

```
①  →  ②成立?  →  循环体  →  ③  →  ②成立?  →  循环体  →  ③  → … → ②不成立 → 退出
```

两个最容易搞错的点：

1. **① 只做一次** —— 但要注意句前提：**指的是"这一次执行到这个 for"的时候**。
   如果这个 for 被套在别的循环里，外层每转一轮，**整个 for 连 ① 一起从头再来一遍**。
   （这正是「给定条件的整数集」里个位每次都从 A 重新数起的原因，见那篇笔记 §八。）
2. **③ 在循环体之后做**，所以在循环体里看到 `i` 时，它还是"这一轮"的值，不是下一轮的

### 四之一、三段各跑几次（2026-10-06 实测，`for (i = 1; i <= 3; i++)`）

| 段 | 名字 | 跑几次 | 说明 |
|---|---|---|---|
| ① 初值 | `i = 1` | **1 次** | 只在这一次 for 里做一次 |
| ② 条件 | `i <= 3` | **4 次** | 比循环体多一次 —— 就是发现不对、把你踢出去的那次 |
| ③ 步进 | `i++` | **3 次** | 每轮末尾一次 |
| — | 循环体 | **3 次** | |

**推论**：条件段永远比循环体多跑一次，且**退出时循环变量会多走一格**。
所以 `for (k = A; k <= A+3; k++)` 正常跑完后 `k` 停在 `A+4`（不是 `A+3`）。

## 五、把 while 改写成 for 的口诀

> **循环上面的初始化 + 括号里的条件 + 体内最后那行步进 → 依次搬进 for 的头部；剩下的（循环体）原样不动。**

**练法**：拿你以前写过的任何一个 while 循环，照这句口诀搬一遍，跑一下对结果。两次输出一样，就说明你搬对了。

## 六、实测（gcc 跑过，两版对照）

| 输入 n | while 版 | for 版 |
|---|---|---|
| 5 | 120 | 120 |
| 1 | 1 | 1 |
| 0 | 1 | 1 |

完全一致 —— 因为**逻辑相同，只是写法不同**。循环这件事，C 给你两种笔，写出来的是同一句话。

## 七、三个小语法点

1. **`i = i + 1` 可以写成 `i++`**。你之前问过 `n++` 和 `++n` 的区别——在 for 的步进格里，这两者**结果相同**，因为这里"用不到表达式的值"，只是单纯把它加一。写 `i++` 更短，是通行写法。
2. **三个格子都可以空着，但分号不能少**：`for (;;)` 的意思是"条件永远为真" = 死循环，等价于 `while (1)`。
3. **循环变量可以就地声明**：`for (int i = 1; i <= n; i++)` —— C99 起支持（你的 `-std=c11` 没问题）。注意这种 `i` 只在这个 for 里活着，出了循环就不认识了；而你 while 版里的 `i` 在循环外也存在。

## 八、以后怎么选：for 还是 while？

| 情况 | 用哪个 | 例子 |
|---|---|---|
| 轮次**数得清**（从 1 到 n、从 n 到 1） | for | 阶乘、求和、遍历数组 |
| 轮次**数不清**，靠条件停 | while | 读到 -1 就停、读到文件尾 |

能力上两者**完全等价**：任何 for 都能改成 while，反之亦然。区别只在"哪个读起来更像你想说的意思"。

## 九、两个边界，自己跑一遍

- **`n = 0`** → 两版都输出 `1`。因为循环一轮都没跑，那个 1 就是**初值本身**，恰好满足数学上的 `0! = 1`。
- **`n = 13`** → 输出一个**错的数**。因为 `13! = 6227020800`，超过 `int` 上限 `2147483647`，装不下就溢出。想算更大得换 `long long` 类型（以后讲）。

### 十之一、这个 try 的结论（2026-10-04 你自己解出来的）

- 三件部件：① 初始化 `i = n`　② 条件 `i > 1`　③ 步进 `i--`
- 条件写 `i > 1` 还是 `i >= 1` **结果完全相同**：`>= 1` 多跑一轮"× 1"，而乘 1 不改变任何数
- 与上一个 try 结论一致：**这种"省一轮"的改动收益 ≈ 0，不值得为它牺牲可读性**
- **但计数器别直接叫 `n`** —— 理由见下节

## 十一、变量的"名字"和"值"：`i` 改成 `n` 到底是什么操作

一组实测（输入 5）：

| 版本 | 循环怎么写 | 最后打印出什么 |
|---|---|---|
| 甲 | 循环变量叫 `i`，输入的 `n` 不动 | `5! = 120` ✓ |
| 乙 | 循环变量叫 `k`（把 `i` 全局改名） | `5! = 120` ✓ |
| 丙 | 循环变量**直接叫 `n`**（拿输入的 `n` 当计数器） | `1! = 120` ← 荒谬 |
| 丁 | `cnt = n;` 复制一份给计数器，`n` 留原件 | `5! = 120` ✓ |

### 三条结论

1. **改名本身不影响结果。** 甲 → 乙：只把 `i` 换成 `k`（所有引用一起改），输出一个字不差。
   **名字只是标签，值才是内容。** VS Code 里选中变量按 **F2** 就是干这件事（Rename Symbol，自动改掉所有引用）。
2. **只改一半会报错。** 循环里改了名、别处还写着旧名 → 编译器报 `'i' undeclared`。
   **这是好事**：漏改能被当场逮住，不会悄悄算错。
3. **真正的风险是"撞名字"。** 循环变量叫 `n`，就和"输入数据 n"用了同一个门牌号 ——
   程序能跑，但 `n` 里原本的 5 被一路吃掉了，最后打出 `1! = 120`。

### 一句判断标准

> 改完之后问自己：**这个位置需要的是哪个值？那个值现在装在哪？**
> 找不到装它的变量，说明前面把信息弄丢了。

- **丙** 的病根：**要算的东西**和**输入的数据**混成了一个变量
- **丁** 的药方：`cnt = n;` 复制一份给计数器，原件留着 —— 多一个变量，换来数据完好

这和 §八 那条"符号 / 数值分离"是**同一个思想**：一件东西一个变量，别让它们互相污染。

## 十二、三种写错，三种下场（2026-10-06 实测，报错原文照抄）

写 for 时最容易栽的三个跟头。**危险程度和"报不报错"不成正比** —— 越安静的越坑人。

### ① 逗号当分号 —— 编译不过（最安全）

```c
for (i = 1, i <= 3, i++)      /* 两个分号写成了逗号 */
```

```
error: expected ';' before ')' token
error: expected expression before ')' token
```

C 把 `i = 1, i <= 3, i++` 当成**一个逗号表达式**（所以另外还报了一条
`warning: right-hand operand of comma expression has no effect`），
于是条件那一格空了 → 语法上就说不通。

> 唯一的好消息：它**当场被逮住**，按报错提示把逗号换回分号就完事了。

### ② 条件里写成 `=` 而不是 `==` —— 死循环（最阴险）⭐

```c
for (i = 1; i = 3; i++)       /* 少打一个等号 */
```

```
warning: suggest parentheses around assignment used as truth value
```

**只是一条 warning，照样能编译出 exe。** 跑起来是这样（本机实测）：

```
循环体第 1 次, 此刻 i = 3
循环体第 2 次, 此刻 i = 3
…（i 永远是 3，永远停不下来）
```

**为什么**：条件那一格 `i = 3` 是**赋值**，每轮它都先把 `i` 按回 3，
再把 3 当"真"返回 → 条件恒真 → 死循环。而且 `i++` 刚加的 1 立刻被下一轮抹掉，
所以循环体里看到的 `i` **永远是 3**。

> 记住：**条件位置要的是"是不是"，赋值给的是"是"**。两者都"能跑"，区别在结果。
> GCC 这条 warning 就是在喊"你是不是想写 `==`"。

### ③ 括号后面多一个分号 —— 零警告，循环空转

```c
for (i = 1; i <= 3; i++);     /* 注意这个分号 */
{
    ...                       /* 这一段已经不属于循环了 */
}
```

编译**一声不吭**。那个分号本身就是一个语句 = **空循环体**，
循环老老实实空转 3 次，后面那个花括号块跟循环没关系，只按普通代码顺序执行一遍。

实测输出：`这一行只会打印一次，此刻 i = 4` —— 打印一次，而且 `i` 已经跑完 3 次加到了 4。

> 这也侧面印证了 §四之一：**循环结束后 `i` 是 4，不是 3。**

### 危险排序

> **① 最安全**（当场报错）　&gt;　**③ 次之**（结果一看就不对）　&gt;　**② 最危险**（像在跑，其实死循环）

**所以每次看到 warning 别跳过** —— ② 这种全靠 warning 提醒，不看就等着程序卡死。

## 十三、第 3 格 = while 花括号里的最后一行（2026-10-06 你自己推出来的）

> 你的原话：「循环里面的第三个路径，就是类似于 while 循环里面的、大括号里面放在最后来做的事情，而且每出一次循环就会做一次。」

**结论：前半句完全正确，后半句要拧一个词。**

```c
/* 这两处的 i++ 是同一件事，只是搬了家 */
for (i = 1; i <= 3; i++)   {  ...  }      /* 在括号第 3 格 */
i = 1;
while (i <= 3)             {  ...  i++;  } /* 在花括号最后一行 */
```

**两版实测输出一个字不差。**

### 次数

| 部件 | 跑几次 |
|---|---|
| 循环体 | 3 次 |
| **步进（第 3 格）** | **3 次** —— 和循环体一样多 |
| 条件（第 2 格） | 4 次 —— 唯一多一次的那个 |

⚠️ **措辞校准**：「每**出**一次循环就做一次」→ 准确说是「**每轮循环体跑完之后做一次**」。
它是**跟着循环体走**的（3 次），**不是**"退出循环的时候做一次"（那样只有 1 次）。
见 §四之一：真正"退出时多跑一次"的是**条件**，不是步进。

### ⭐ 但有一处它俩并不等价：碰到 `continue` 的时候

`continue` 的作用是「跳过循环体**剩下**的部分，直接进下一轮」。所以：

| | 步进在哪 | 遇到 `continue` | 实测结果 |
|---|---|---|---|
| **for 版** | 括号里，**不属于循环体** | **跳不过去**，照样执行 | 输出 `1 2 4 5`，正常退出 ✓ |
| **while 版** | 就是循环体的一行 | **被一起跳过** | 输出 `1 2` 之后 i 永远是 3，**死循环** |

实测（两版逻辑完全相同，只在 `i == 3` 处 `continue`）：

```
for   版: 1 2 [i=3 跳过一次] 4 5     → 正常跑完
while 版: 1 2 [i=3 再来] [i=3 再来] [i=3 再来] … → 手动 break 才停
```

> **这就是 for 存在的真正理由** —— 不只是"写起来短"。
> 它把步进藏进括号、挪出循环体，堵住了「`continue` 顺手把计数器也跳过去」这个洞。
> while 里想避开这个坑，得把 `i++` 挪到 `while` 那一行的括号里（`while (i++ <= 3)`，但可读性差）。

## 十四、初值格：能不能留空？能不能就地声明？（2026-10-06 你自己问的）

> 你的原话：「for 版的初始化，我前面可以不用再定义变量了？或者我前面定义变量之后，直接在那个初始化格打一个分号就可以了？」

**两问答案都是「能」，但每种各带一个条件。**

### 甲、就地声明：`for (int i = 1; i <= 3; i++)`

合法（C99 起支持，你的 `-std=c11` 没问题）。

**好处**：少写一行；而且**这个变量天生每轮重做一份 → 重置是白送的**（内层循环的福利，见下面「留空的坑」那一节）。
**代价**：出了这个大括号，`i` 就不存在了。实测故意在循环外用一下：

```
error: 'i' undeclared (first use in this function)
```

### 乙、前面定义好、第 1 格留空：`for (; i <= 3; i++)`

也合法，**但两个分号必须都在**（空的是"那一格的内容"，不是分号本身）。

**好处**：`i` 出了循环还活着。实测能读到它跑完后的值：

```
循环里面: i = 1 / 2 / 3
循环外面还能用: i = 4      ← 出循环后 i = 4，还在
```

**前提**：**进到这个 for 的时候，变量必须已经是你要的初值。**
留空的含义是「初值那格我不写了，你自己从上文接着用」，不是「空着不管」。

### ⭐ 留空的坑：内层循环留空 = 定时炸弹

三组代码只差「第 1 格写什么」，实测输出（十位 j 从 2 试到 3，个位只到 3）：

| 内层第 1 格 | j=2 那一轮 | j=3 那一轮 |
|---|---|---|
| **留空**（k 只在循环外赋过一次 2） | `222  223` | **（空的，一个都没出）** |
| `k = 2` | `222  223` | `232  233` |
| `int k = 2`（就地声明） | `222  223` | `232  233` |

**为什么留空那组第二轮是空的**：`k` 跑完停在 4（因为 `k++` 多加了一次，见 §四之一），
4 > 3 → 第二轮**一次都进不去**。

> 这就是你在「给定条件的整数集」里会遇到的病根的**同一件事**：内层忘了重置。

### ⭐⭐ 再往下一层：变量不会自己「回到起点」（2026-10-06 追问）

> 你的原话：「还是不懂，因为它是从内循环开始吗？」

**你以为的**：每一轮 j 换新，内层 k 会自动从头再数一遍。
**实际**：C 里**没有**「自动从头」这回事。`for` 语句只干一件事 ——
**拿 k 现在的值去比条件**。它进场时 k 是多少，就从多少开始。

#### 最小实验：两个 for 前后接着，第 1 格都留空

```c
int n = 2;                  /* 起点：全篇只在这一处给过 */
for (; n <= 3; n++) ...     /* 打出 2、3，退场时 n = 4 */
for (; n <= 3; n++) ...     /* 一个都没打 */
```

实测输出：

```
第 1 个 for 进场: n = 2
        n = 2
        n = 3
第 1 个 for 退场: n = 4
第 2 个 for 进场: n = 4   <-- 没回到 2
第 2 个 for 一个都没打
```

**起点只发一次票，两轮循环只够用一轮。**

#### 带「进场值」的完整轨迹（2026-10-06 实测）

在每轮 j 的进出场各打印一次 k。场景：i 固定 2，j 走 2→3，k 范围 2～3（为看清起步位置，暂不加筛选）。

```
===== A) 内层第 1 格留空 =====
  [十位层 j=2 进场] k 现在 = 2
       打印 222
       打印 223
  [十位层 j=2 退场] k 停在 4
  [十位层 j=3 进场] k 现在 = 4        <-- 上一轮用剩的 4
  [十位层 j=3 退场] k 停在 4          <-- 循环体一次都没进

===== B) 内层第 1 格写 k = 2 =====
  [十位层 j=2 进场] k 现在 = 2
       打印 222
       打印 223
  [十位层 j=2 退场] k 停在 4
  [十位层 j=3 进场] k 现在 = 4
       打印 232                       <-- 被 for 里的 k = 2 按回去了
       打印 233
  [十位层 j=3 退场] k 停在 4
```

**盯这两行**：B 组 j=3 进场时 k 也是 4，但 `for (k = 2; ...)` 里的 `k = 2` 立刻把它按回 2。

#### 一句话

> **`for (k = A; ...)` 里那个 `k = A`，就是把「从头」这两个字亲手写出来。**
> 你不写，它就不从头 —— 它接着上一轮的尾巴继续。

#### 别搞混：`for` 的三格，跑的次数不一样

| 位置 | 跑几次 | 作用 |
|---|---|---|
| 第 1 格 `k = A` | **每轮外层一次** | 它就是「重置」本尊 |
| 第 2 格 条件 | 每轮外层 **多次**（比循环体多一次） | 决定进不进、什么时候退出 |
| 第 3 格 步进 | 每个 k 值一次 | 往前走一格 |

（第 1 格"只做一次"这个说法，指的是**这一次执行到这个 for 的时候**，详见 §四之一。）

#### 顺带：留空的前提是「外面已经声明过」

留空 ≠ 不管。如果变量压根没声明：

```c
for (; i <= 3; i++) { ... }   /* i 从头到尾没出现过 */
```

实测报错原文：

```
error: 'i' undeclared (first use in this function)
```

**留空的意思是「用外面那个」，不是「凭空造一个」。**

### 怎么选（决策表）

| 情况 | 怎么写 | 理由 |
|---|---|---|
| 变量只在循环里用 | `for (int i = A; ...)` **就地声明** | 少一行，还白拿"每轮重置" |
| 变量出了循环还要用（要打印它、或两层共用一个） | 前面定义，第 1 格留空 | 出循环后变量还在 |
| **内层循环的计数器** | **必须**保证每轮重置 | 写 `k = A` 或就地声明，**绝不能留空** |

**回到整数集**：个位那层完全可以写成

```c
for (int k = A; k <= A + 3; k++)
```

这样"每轮从 A 重新数"就是**天生的**，不用你手写 `k = A` 去救它。
