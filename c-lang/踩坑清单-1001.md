# 10/1 踩坑清单（今天真实发生的，每条都有实测证据）

> 用途：明天写新程序前扫一眼；面试前复习"我能讲清哪些坑"。
> 分三类：**编译错**（gcc 会喊）、**运行错**（gcc 不喊，最阴）、**操作错**（环境/输入）。

---

## 一、编译错误：gcc 会大喊，看得见

### 1. 只修第一条错误 —— 剩下的多半是"连坐"假错
第 5 行一处引号写错，带出后面三条**假的**错误：

| 报错 | 真假 | 真相 |
|---|---|---|
| `5:99: expected ';' before ':' token` | **真** | 只有这条要改 |
| `9:20: 'foot' undeclared` | 假 | `int foot;` 明明在第 6 行 |
| `11:5: expected ')' before 'printf'` | 假 | 上一条的余波 |
| `13:1: expected ';' before '}' token` | 假 | 上一条的余波 |

实测：修完第 5 行，其余自动消失。**gcc 的报错顺序里，第一条才是线索，后面是噪音。**

### 2. 字符串被半角引号"提前关门"（今天最大的坑）
```c
printf("请分别输入身高的英尺和英寸，"”如输入\"57\"表示5英尺7英寸:"):
```
- 第 27 个字符是**半角** `"` → 字符串从这儿就结束了
- 紧跟的全角 `”` 和整段正文被当成代码 → 一串 stray + `expected ')' before string constant`
- 行尾多余的 `:` → `5:99 expected ';' before ':'`

**口诀：字符串的"门"必须是成对的半角 `"`，且成对出现在同一行；字符串里要显示引号就写 `\"`。**

### 3. 全角标点写在字符串**里面**是合法的
`："`，`：` 这些全角标点放在引号内**完全没问题**（已实测编译通过）。
真凶是**引号的配对位置**，不是标点全角半角 —— 别被"中文标点会报错"误导。

### 4. 多余的一个引号
`scanf("%d %d",&foot,&inch");` — `inch"` 多一个 `"` → `9:5: missing terminating " character`，并连坐出上面那一堆假错。

### 5. `#include <stadio.h>` 拼错
实测报错：`tempCodeRunnerFile.c:1:20: fatal error: stadio.h: No such file or directory`。
正确是 **st<u>u</u>dio**（Standard Input/Output）。

### 6. 逗号跑进引号里
```c
printf("%d\n,"11/3*3);   /* ✗ 实测：5:19 expected ')' before numeric constant */
printf("%d\n", 11/3*3);  /* ✓ */
```
**引号里 = 格式说明，引号外 = 要填的东西。** 这条对 scanf/printf 都成立。

### 7. 列号是**字节**偏移，不是第几个字
中文一个字占 3 字节，所以 `5:99` 指的是第 99 个**字节**。想对上"哪个字符"，用 python 逐字符打印码位 + 字节偏移。

## 二、运行时错误：gcc 一声不吭，只能靠"结果对不对"发现（最阴）

### 1. 整数除法 —— 小数被砍掉，不报错不警告
```c
inch/12      /* ✗ 7/12 == 0（截断，不是四舍五入） */
inch/12.0    /* ✓ 有 double 参与才做浮点除法 */
```
实测（`5 7`）：`inch/12` → `1.524000`（错），`inch/12.0` → `1.701800`（对）。
另一个：`11/3*3` 输出 **9** 不是 11（`11/3` 先截成 3）。
**发现方法只有一个：拿笔算一遍，看结果对不对。**

### 2. 未初始化变量 —— scanf 没读到，变量里是垃圾值
今天出现两次，都**不报错、不崩溃**，只给离谱的数：
- 只输一个数（`5` 后结束）→ `1.549400`（`inch` 没赋值）
- 输入 `1,30`（逗号）→ `时间差是4225567小时`

**口诀：结果离谱 → 先怀疑"这个变量到底有没有被赋值"。**

### 3. 输入格式必须和格式串一致
格式串 `"%d %d"` 要求两个整数用**空格或回车**分隔。
敲 `1,30` → 第二个 `%d` 一看到逗号就罢工，后面的变量全没赋值（就是上面那个 4225567）。
想要逗号分隔，就把格式串写成 `"%d,%d"` —— **引号里写了什么，你就照着敲什么。**

### 4. scanf 每个变量前都要 `&`
`scanf("%d %d",&hour2,minute2);` ← `minute2` 前漏了 `&`。

### 5. 逻辑顺序：`时间差` 算的是 t2 − t1
输入 `2 30` 再 `1 15` → `时间差是-1小时 -15分。`（实测）
要正数就**早的时间先输**：`1 15` 回车 `2 30` → `1小时 15分。`
（程序还不会判断谁减谁，等学 `if` 再处理。）

## 三、`&` 和 `+` 长得像，但完全两回事

| 符号 | 含义 | 用在哪 |
|---|---|---|
| `&` | **取地址**：把变量的"门牌号"交给 scanf，它才知道把读到的数放进哪 | **只**用在 scanf 的参数里 |
| `+` | 加法 | 算术表达式 |

今天第 11/12 行把 `+` 写成了 `&`（想做加法），第 9 行该给地址的又漏了 —— 正好写反两个。

## 四、VS Code / 终端操作

1. **幽灵标签（斜体 + 白点）**：代码根本不在你的文件夹里，Code Runner 只把它复制成 `tempCodeRunnerFile.c`；关掉标签或被下一次运行覆盖就丢了。今天靠 `%APPDATA%\Code\Backups\<窗口ID>\untitled\<哈希>` 抢救回来一次。
   → **新建文件后立刻 `Ctrl+Shift+S` 命名。**
2. **保存会补 `.c`，但别依赖**：VS Code 按语言模式补后缀；换记事本/Dev-C++ 就不会补。自己敲全 `名字.c`。
   gcc **只认 `.c`**：同样的代码存成无后缀 → 实测 `file not recognized: File format not recognized`。
3. **键盘焦点**：`Ctrl+S` 只作用于当前聚焦区域，焦点在终端就什么都不会发生。点回代码区再 `Ctrl+Alt+N`（或点右上角 ▷ —— 两者完全等效）。
4. **终端有两层等待**：`$` 提示符 = bash 在等**命令**；程序跑起来后 = 程序在等**数据**。把 `6 7` 敲在 `$` 后 → `bash: 6: command not found`。
5. **编译失败不生成 exe，程序压根跑不起来** —— 你只会看到报错列表，看不到运行结果，所以"编译错"和"结果错"是两回事。
6. `bash: Sbash: command not found` = 运行命令里混进了多余字符（`S`）。配置本身没问题（已手动验证同一条命令正常）。
7. **源码一律 UTF-8**，靠编译参数 `-fexec-charset=GBK` 适配终端；别去改右下角的编码。
8. 文件名别带空格（今天的 `double 变浮点数计算 .c` 就是 `.c` 前多了个空格，能跑但以后在命令行里容易出事）。
